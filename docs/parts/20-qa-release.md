# 20. QA·릴리즈·앱스토어

> **한 줄 목적:** 40~70대가 도움 없이 쓸 수 있고 "우리 교회의 명예"가 위조되지 않는다는 신뢰 위에서, 크래시 없이 심사를 통과해 안전하게 단계적으로 출시하고 되돌릴 수 있게 만드는 품질·릴리즈·스토어 실행 체계.

이 문서는 PRD 제품 원칙과 다음과 같이 정합한다.
- **중장년이 기본값이다** → 디바이스 매트릭스를 저사양 구형 갤럭시·최대 텍스트스케일·큰글씨 기준으로 잡고, 접근성 QA를 색약/스크린리더/동적폰트/야간모드까지 필수 게이트로 승격한다.
- **명예로 경쟁한다** → 점수·콤보·티어·초대의 서버권위 무결성 검증(안티치트 QA)을 P0 회귀 스위트로 상시 실행한다. 명예가 위조되면 제품의 유일한 차별점이 붕괴하므로 이는 "차단(blocker)" 등급이다.
- **교회가 팀이다** → 리더보드/교회대항/주간리셋을 회귀·부하 테스트의 핵심 시나리오로 두고, 월요일 00시 전역 리셋(썬더링허드)을 성능 게이트로 명시한다.
- **매일의 습관에 얹는다** → 새벽/출퇴근/취침 전 사용 맥락(약전파·오프라인·야간모드·야간푸시 규제)을 폴백 QA와 릴리즈 정책에 반영한다.

## 20.1 테스트 전략 개요

### 20.1.1 테스트 피라미드와 커버리지 목표

Flutter 단일 코드베이스이므로 로직은 Dart 단위 테스트로 두껍게, 화면은 위젯/골든으로 중간, 네이티브 경계(IAP·광고·푸시·딥링크·ATT)만 실기기 E2E/수동으로 얇게 가져간다.

| 레이어 | 도구(권고) | 대상 | 커버리지/규모 목표 | CI 게이트 |
|---|---|---|---|---|
| 단위(Unit) | `flutter_test` + `mocktail` | 도메인 로직: 포인트 산정(10/15/25pt·콤보 +10%/+25%), 티어 임계(겨자씨~면류관), 재출제 20%·최근정답 하향, 초대 유효성 3조건, 안티치트 규칙(1.5초 룰), 주간경계(월 00시 KST) 계산 | **도메인/로직 레이어 80%+ 라인**, 산정·티어·초대·주간경계는 **분기 100%** | PR 필수 통과 |
| 위젯(Widget) | `flutter_test` (`pumpWidget`) | 퀴즈 1문제1화면, 결과요약, 리더보드 3탭, 온보딩 단계, 신고 바텀시트 | 핵심 20개 화면 상호작용 스모크 | PR 필수 |
| 골든(Golden) | `alchemist` 또는 `golden_toolkit` | 큰글씨·텍스트스케일 **20.3.3 확정 배율 세트**(1.0 / 중간단계 / design 11.3.3 확정 결합 클램프 상한) × 소/대 화면에서 레이아웃 깨짐 방지 | 핵심 8개 화면 × 스케일 세트(20.3.3) 골든 매트릭스 | PR 필수(픽셀 diff) |
| 통합(Integration) | `integration_test` + `patrol` | 화면 간 플로우 + 네이티브 권한/웹뷰/딥링크. Patrol로 카카오 로그인 웹뷰·ATT·푸시 권한 다이얼로그 제어 | P0 시나리오 6종(20.5) | 나이틀리(Test Lab) |
| E2E(디바이스팜) | Firebase **Test Lab** (Android Robo+Instrumented, iOS) | 실기기 매트릭스 자동 실행, 콜드스타트/크래시 캡처 | 디바이스 매트릭스 Tier1 전수 | 릴리즈 후보(RC)마다 |
| 수동(Manual) | 체크리스트 + 실사용자 세션 | IAP 샌드박스, ATT 실동작, 광고 실노출, 심사 데모 계정, **중장년 사용성(실사용자 5~8명, 40~70대)** | RC마다 + 파일럿 | 출시 게이트 |

### 20.1.2 테스트 가능성(Testability) 요구 — client 의존

QA가 결정적으로 검증하려면 **client 파트**가 다음을 제공해야 한다(인터페이스 요청).
- 빌드 플레이버: `dev` / `staging` / `prod` (별도 applicationId suffix `.dev` `.stg`, 별도 번들 ID)로 스토어 프로덕션 오염 없이 병렬 설치.
- 결정적 시드 주입: 퀴즈 출제·랜덤 재출제에 테스트 전용 시드 주입 훅(스테이징 한정)으로 재현 가능한 회귀.
- 히든 QA 메뉴(스테이징): 주간경계 강제 트리거, 티어 강제 세팅, 광고 강제/차단, 서버시간 오프셋 표시.
- Semantics 라벨: 모든 인터랙션 위젯에 `Semantics(label:)` 부여(접근성 QA·자동화 셀렉터 겸용).
- Remote Config 플래그를 테스트에서 오버라이드 가능하게 노출.

## 20.2 테스트 레이어별 상세

### 20.2.1 단위 테스트 — "명예 무결성"의 1차 방어선
포인트/티어/초대는 제품의 심장이므로 표 기반 케이스로 전수 검증한다.

- **포인트 산정**: 난이도별 신규정답 10/15/25pt, 과거정답 재출제 시 감차, 콤보 5연속 +10%·10연속 +25% 경계값(4→5, 9→10, 10→11), 오답 0pt, 스피드OX 1/3(v1.1)·일일상한(정규 30문제분).
- **티어 판정**: 임계 직전/직후(2,999→3,000 등불, 9,999→10,000 감람나무 …), **하락 없음** 불변식(포인트 차감이 티어를 내리지 않음).
- **파밍 방지**: 재출제 20% 확률 분포, 최근정답 출제우선순위 하향, **문제당 1.5초 미만 연타 반복 시 세션포인트 무효**(단, 스피드OX 제외).
- **초대 유효성**: (신규가입 ∧ 교회등록 ∧ 퀴즈20문제완료) 3조건 AND — 부분충족은 '대기중', 동일기기 차단, 일일 인정상한 5.
- **주간경계**: 월요일 00시 KST 리셋 계산(경계 직전 23:59:59 / 직후 00:00:00), DST 없는 KST 고정, 재외 타임존은 openQuestion(20.16).

### 20.2.2 위젯·골든 — 큰글씨 레이아웃 파괴 방지
중장년 기본값의 최대 리스크는 **글자 키우면 화면이 깨지는 것**이다. 골든 테스트를 텍스트스케일 매트릭스로 강제한다.
- 대상 화면: 온보딩(큰글씨 선택·진단문제), 퀴즈(선택지 4버튼 56pt+), 결과요약, 리더보드(내 순위 상단고정), 티어 축하카드, 교회 상세, 신고 바텀시트, 홈(오늘의 말씀).
- 매트릭스: 텍스트스케일 {1.0, 중간단계, **design 11.3.3 확정 결합 클램프 상한**} × 화면폭 {iPhone SE 375pt, 저가 갤럭시 360dp, 대형 430pt}. 확정 상한을 초과하는 OS 접근성 초대형 스케일 스냅샷은 **비차단 강건성** 검증으로만 둔다.
- 실패 기준: 선택지 텍스트 말줄임(…)·버튼 밖 오버플로우·본문 18pt 미만·선택지 버튼 56pt 미만(**전 배율에서 하한 유지**)·터치타깃 겹침.

### 20.2.3 통합·E2E — 네이티브 경계
Patrol로 자동화하되 아래는 **수동 필수**(자동화 신뢰도가 낮은 영역).
- IAP: 구독 결제/복원/자동갱신/영수증 서버검증(가짜 영수증 거부)은 스토어 샌드박스 수동.
- ATT: iOS 추적 허용/거부 각각에서 광고 정상·개인정보 처리 정합.
- 카카오 로그인: 웹뷰 흐름·계정 전환.
- 딥링크 초대: 카톡 공유→설치→자동 귀속(코드 미입력) 실기기.

### 20.3.3 텍스트스케일·큰글씨 매트릭스(필수)
OS 시스템 폰트 확대와 앱 내 '큰글씨' 모드를 곱집합으로 검증한다.
- OS 폰트 스케일: iOS Dynamic Type(기본~AX 접근성 크기), Android 글꼴 크기 {작게, 기본, 크게, 가장 크게} + 접근성 화면확대.
- 앱 내 큰글씨: **3단계 토글(보통/큰/아주큰)**. 3단계 배율값과 OS×앱 곱연산 **결합 클램프 상한**은 **design 11.3.3의 단일 배율 테이블을 유일 출처로 참조**하며 design·ux·client·qa가 **동일 수치**를 쓴다(현재 파트별 상이: design/ux 상한 1.3, client 클램프 1.6, qa 종전 2.0 — RC 전 단일 확정 필수, 20.15).
- **공통 하한 규칙**: 본문 18pt·선택지 버튼 56pt 하한은 **전 배율에서 유지**(design이 확정하는 최대 클램프는 이 하한이 깨지지 않는 조건에서 산정한다).
- **합격선(차단)**: design 11.3.3 확정 **결합 클램프 상한까지** 주요 6개 시나리오 전 화면 무파괴·무말줄임·전 버튼 탭 가능. 앱은 `MediaQuery`로 확정 클램프에서 상한 처리하고, 그 이상(OS 접근성 초대형)은 **비차단 강건성 스냅샷**으로만 검증한다.
- **정정**: 종전 'QA 독자 합격선 2.0(=200%)·iOS 클램프 1.8~2.0' 표기는 design/client 클램프와 어긋나 회귀 기준이 성립하지 않으므로 폐기하고, 골든/회귀 배율 세트를 확정 클램프에 정렬한다.

## 20.4 접근성 QA 체크리스트

목표 기준: **WCAG 2.1 AA**. PRD의 '큰글씨'는 최소요건일 뿐 아래를 게이트로 승격한다(중장년·색약·새벽 사용 맥락).

| # | 항목 | 합격 기준 | 검증 방법 | 소유(의존) |
|---|---|---|---|---|
| A1 | 색상 단독 신호 금지 | 정답=녹/오답=적을 **아이콘(✓/✗)+텍스트+모양**으로 이중부호화. 색약(적록 남성 8%)에서 구분 가능 | 색약 시뮬레이터 + 흑백 스크린샷 검수 | design |
| A2 | 대비비 | 본문 4.5:1, 큰글자·UI요소 3:1 이상 | 대비 측정(대비 검사 도구) | design |
| A3 | 스크린리더 | TalkBack/VoiceOver로 온보딩→퀴즈→채점→리더보드 완주 가능. 모든 버튼 라벨·역할·상태 발화("정답입니다", "3번 선택지") | 실기기 수동 완주 | client |
| A4 | 동적 폰트 | **20.3.3 확정 결합 클램프 상한에서 무파괴**(20.3.3와 연동, 18pt/56pt 하한 유지) | 골든 + 수동 | client/design |
| A5 | 야간/다크 모드 | 새벽기도 맥락 저조도 화면. 다크모드에서 대비·아이콘 유지 | 매 화면 라이트/다크 스냅샷 | design |
| A6 | 터치타깃·오탭방지 | 선택지 56pt+·간격 8pt+, 인접 버튼 오탭 방지, 오답 확정 전 되돌림 여지 없음 명확화 | 수동(떨림 있는 손 시뮬레이션) | ux |
| A7 | 햅틱·피드백 | 정답/오답 시 시각+햅틱(진동) 피드백, 소리 옵션 | 실기기 | client |
| A8 | 모션·타이머 | 자동 넘어가는 화면 없음(사용자 탭으로 진행), 애니메이션 감소 설정 존중 | 수동 | client |
| A9 | 광고 접근성 | 전면광고 닫기(X) 버튼이 스케일 확대에서도 탭 가능, 오탭 유발 배치 아님 | 수동 | monetization |

> 접근성 QA는 **자동화가 어렵다.** 파일럿 이전에 40~70대 실사용자 5~8명 대상 **무보조 완주 세션**(온보딩~첫 퀴즈~교회등록)을 1회 실시하고, 이탈 지점을 릴리즈 게이트 항목으로 기록한다(ux·org 협업).

## 20.6 안티치트·명예 무결성 QA (high 갭 해소)

명예 리더보드가 유일 차별점이므로, "우리 교회를 위해" 조작할 강한 사회적 유인을 전제로 **위조 시도를 재현 테스트**한다. 이는 server 파트의 서버권위 설계를 QA가 검증하는 것이며, 설계 부재 시 **출시 차단 사유**로 상신한다.

### 20.6.1 서버권위 검증(요청 인터셉트 테스트)
- 도구: mitmproxy/Charles로 스테이징 트래픽 가로채기.
- **안티치트 토큰 모델(확정)**: server 14.6의 **문항별 serve_token(HMAC)+nonce**를 단일 모델로 채택한다. client는 `/quiz/next` 응답의 문항별 serve_token을 저장(13.4.2 버퍼링에 캡처 명시 요청)해 해당 attempt 제출 시 되돌려준다. client 13.5.3의 세션키 X-Signature 중복 서명은 **제거하거나 serve_token과의 관계를 명문화**한다(20.15). 전면 요청서명은 MVP 과설계이므로 QA는 serve_token 바인딩 기준으로 인터셉트 테스트를 작성한다.
- 케이스:
  1. 점수 제출 페이로드를 999,999pt로 변조 → **서버가 재계산/거부**, 리더보드 미반영.
  2. 콤보/티어를 클라이언트에서 조작 → 서버 판정으로 무시.
  3. 유효 제출 **재전송(replay)** → 서버 dedupe(멱등키/논스)로 중복 무시.
  4. **serve_token 누락/위조/타 문항 토큰 재사용/만료** 제출 → 서버 거부(문항-attempt 바인딩 불일치).
  5. `/quiz/next` 응답에 **정답(answer_index)·해설·근거 미포함** 불변식 확인(정답은 채점 응답에서만 노출 — 오프라인 정책과 정합, 20.7.4).
- 합격: 클라이언트 계산은 화면 표시용일 뿐, **점수의 진실은 서버**이며 serve_token 바인딩이 모든 케이스에서 성립.

### 20.6.2 무결성·환경 탐지
- 루팅/탈옥 기기에서 실행 → 서버가 플래그(차단 또는 검토큐), 앱은 정상 크래시 없이 동작.
- 서버시간 기준 출석/연속(기기 시계 조작으로 출석·연속 배지 획득 시도 → 서버시간으로 무효).
- 다계정 담합(여러 카카오 계정·다기기로 자기 교회 부양): 계정군집 탐지는 server·data 담당, QA는 **검토큐에 이상패턴이 올라오는지** 종단 검증.

### 20.6.3 안티치트 오탐 이의제기(low 갭 해소)
지식 뛰어난 권사님의 정당한 빠른 응답이 '1.5초 룰'에 걸릴 수 있음. QA는 다음을 검증한다.
- 무효 발생 시 **명확한 한국어 안내**("너무 빠른 연속 응답으로 이번 세션 점수는 반영되지 않았어요") + 다음 세션 정상 복귀.
- 이의/소명 경로(CS 채널, 20.15 ops) 노출.
- 오탐률 계측 이벤트(data)로 파일럿 중 임계 재튜닝.

### 20.6.4 LLM 자동수정 손상 방어(medium 갭, v1.1) — 단일 가드레일 규격
무인 오타 자동수정의 콘텐츠 훼손 리스크를 막기 위해, content(18.9.5/18.9.6)·server(14.11.2)·ops(21.3.1)·qa가 **동일한 화이트리스트 규격**을 공유한다(종전 파트별 상이: 허용 필드 {질문,해설} vs 지문만, 편집거리 ≤5&원문10% vs ≤2, 신뢰도 ≥0.90 vs ≥0.95). QA는 이 규격을 **배포 게이트 전 프리즈**하고 금지 골든셋으로 검증한다.

| 파라미터 | 확정 규격 |
|---|---|
| 허용 필드 | **문제 지문(question)만**. **해설·선택지·정답·근거구절 텍스트는 자동수정 금지**(운영 21.3.1의 엄격 규칙 채택 — 콘텐츠 18.9.6의 '해설 자동수정 허용'은 미채택) |
| 편집거리 상한 | **≤2자** 그리고 diff가 지문에 한정 |
| 최소 신뢰도 | **≥0.95** + **2모델 합의** |
| 불변 diff가드 | 정답 인덱스·선택지·근거구절·**해설** 바이트 불변(변경 감지 시 자동 반려→인간검수) |
| 일 상한 | **20건/일** |
| 관찰창·롤백 | **48h 관찰창**, 원탭 롤백, 원문 대비 훼손 감사로그 |

- **골든 방어**: '자동수정 금지' 정상 문항 100개(content 20.15 제공)를 넣어 LLM이 훼손하지 않는지 회귀. 위 불변 필드가 1바이트라도 바뀌면 실패.
- **초기값 `llm_autofix_enabled=false`**로 출시 후 관측하며, 위 규격 충족·48h 무사고 확인 후 점진 개방(content·qa·server·ops 공동).

### 20.6.5 보상형 광고 공정성 — 교회 대항 제외(medium 갭, v1.1)
monetization(15.2.6/15.11)은 보상형 2배 포인트를 교회 대항 점수(상위20 주간합산)에서 제외하도록 server에 위임하나, 현 server 리더보드(14.7~14.8/14.10)는 개인 주간포인트를 그대로 top20 합산하므로 보상형 배율분이 개인→교회점수로 유입돼 '명예 불가침(광고시청이 리더보드에 영향 금지)'과 유일 차별점을 훼손한다.
- **QA 검증**: 보상형 유래 가산분이 point_ledger/주간집계에서 **별도 entry_type/플래그로 태깅**되어 교회 대항 합산에서 제외되는지(개인 점수엔 반영) 어뷰징/공정성 회귀에 추가.
- **v1 선반영 요구(server)**: 보상형은 v1.1 스코프이나 **v1 집계 스키마에 태깅 근거가 없으면 출시 후 재작업**이 되므로, v1 스키마 선반영을 요구한다(20.15). monetization의 '가드레일 확정 전 v1.1 배포 금지'를 server 확약과 연결한다.

- **부하 테스트(server 공동)**: MAU 10만·DAU 25% 가정, 월요일 06~09시 스파이크에서 상위20명 주간합산 집계 API가 목표 지연 내 응답하는지 k6/Locust 부하 시나리오로 검증. 결과 미충족 시 리셋 시점(월 00시 vs 주일 저녁, openQuestion 4) 재검토 근거로 제출.

### 20.7.4 오프라인·약전파·광고실패 폴백(medium 갭, P2 지하철 맥락)
- **오프라인 채점 모델(확정)**: ux(12.7)·server(14.9.1)의 **프리페치 + 제출 큐잉 → 재연결 시 서버 채점** 단일 모델을 채택한다. 오프라인 중에는 **로컬 정답키를 내려받지 않고 정오(정답/오답)를 표시하지 않으며**(재연결 후 서버 채점 결과로 표시), 안티치트 불변식(정답은 채점 응답에서만, 20.6.1 케이스 5)을 유지한다. 약전파 UX 저하(즉시 피드백 없음)는 **명시 수용**.
- **충돌 상신(blocker 후보)**: client(13.4.1/13.5.1)의 '오프라인팩(암호화 로컬 정답키 다운로드형 즉시 채점)'과 `GET /quiz/offline-pack`·`POST /quiz/answers/batch` 전제는 server(14.5/14.7.1)가 제공하지 않고 안티치트 원칙과 충돌한다. **착수 전 OpenAPI로 client·server가 엔드포인트·명칭(quiz/attempts·batch·offline-pack·push-token·invite/accept·invite/me)을 단일 확정**하지 않으면 QA는 출시 차단 사유로 상신한다(20.15). 오프라인 즉시 피드백을 필수 요건으로 승격할 경우에만, server가 provisional 정답키 다운로드·상한·재검증·회수 규칙을 스펙에 명문화한 뒤 별도 계약으로 검증한다.
- **광고 로드 실패 시 진행을 절대 차단하지 않음**(2초 내 미준비 시 스킵) — 결정 확정, monetization과 인터페이스.
- 저사양 안드로이드: 광고 SDK 초기화가 콜드스타트를 늦추지 않도록 지연 초기화, QA가 콜드스타트 회귀 감시.

### 20.10.2 스토어 심사 대응 — 리젝 리스크 사전 차단

**Apple**
- **Guideline 4.8 (Sign in with Apple)**: 카카오 단독은 제3자 소셜 로그인 단독 사용이므로 **Sign in with Apple 병행 필수**. PRD도 이를 인지("+Apple 심사요건"). QA는 **제출 전 Apple 로그인 실동작을 P0로 확인** — 미구현 시 확실한 리젝.
- **Guideline 5.1.1(v) 계정 삭제**: **인앱 회원탈퇴 필수**(2022~). 탈퇴 시 포인트·기여·초대귀속 처리 규칙(legal/server, high 갭)까지 화면 연결.
- **Guideline 3.1.1 IAP**: 구독은 Apple IAP만, 외부결제 링크 금지. 자동갱신 고지·복원·약관·개인정보 링크.

- **Guideline 2.1 완전성**: **심사자용 데모 계정 제공**. 카카오/Apple 로그인·교회등록을 심사자가 재현 못할 수 있으므로 **데모 모드 또는 사전세팅 계정 + 심사 메모**에 로그인 절차·교회검색 예시·구독 테스트 방법 상세 기재.
- 사행성(1.4.3): 명예 포인트=현금성 아님이므로 도박 아님. 단 심사 메모에 "포인트는 환전·소비 불가 순수 명예"임을 1줄 명시해 오해 차단.

**Google Play**
- **데이터 안전(Data safety)**: 종교(민감)·기기식별자·광고 수집 정확 신고. 미신고/불일치는 정책 위반.

### 20.10.3 연령등급·미성년·GRAC(high 갭 해소)
- **연령게이트**: 온보딩에서 생년(또는 만14세 이상 확인) 수집 → **만14세 미만은 법정대리인 동의 없이는 진입 제한**(PIPA). 성경퀴즈는 주일학교 아동을 강하게 유입하므로 필수(legal 결정).
- **미성년 실명 전국 노출 방지**: 미성년은 리더보드 표시명을 실명 대신 별명/마스킹, 행태광고 제한(아동 맞춤광고 off). QA는 미성년 플래그 계정으로 노출·광고 동작 검증.
- **한국 게임물 등급(GRAC)**: Apple/Google은 **자체등급분류사업자** → 스토어 IARC 설문으로 자동 등급. 설문 응답 정확성(폭력/사행성/광고) 확보. **v1은 개신교 한정**이므로 등급 코멘트에 종교 소구 반영.
- **인허가(low 갭)**: 구독=전자상거래 → **통신판매업 신고**, 자동갱신 청약철회·표준약관(legal/ops). 출시 게이트에 포함.

### 20.10.4 야간 광고성 푸시(medium 갭) — 스토어보다 국내법
- 새벽기도 리마인드·주간마감 D-1은 **광고성**일 수 있어 정보통신망법상 **21시~08시 발송 시 별도 야간 수신동의** 필요.
- 정책 결정: 정보성(교회순위 변동 등)과 광고성 구분, 야간 발송은 `push_night_enabled=false` 기본 + 야간동의 받은 사용자만 개방. QA는 야간 시간대 푸시 억제를 검증(client·legal).

## 20.11 개인정보·저작권 — 심사·출시 전 필수 확인(high 갭, QA 게이트화)

QA/릴리즈는 아래를 **법무 사인오프 없이는 출시 차단**으로 취급한다(legal 소유, QA는 게이트 검증).
- **종교=민감정보(PIPA §23)**: 종교·교회소속을 **별도 명시동의**로 수집, 전국 공개 범위 고지, 처리방침 반영, **B2B 목적외이용 별도 동의**. 무동의 운영은 'B2B 자산화' 목표 자체가 위법. QA는 동의 화면 존재·거부 시 흐름 검증.
- **회원 라이프사이클**: 탈퇴/열람·정정·삭제·처리정지 경로, 카카오 수집항목 고지, 광고식별자·ATT 동의, 국외 SDK(AdMob·Firebase) **국외이전 동의** — 앱심사·PIPA 필수. QA는 각 화면 실존·동작 확인.
- **저작권(개역개정 축자 표시)**: F1 근거구절·F9 원문 사용은 본문 축자 복제·전송. "내용이해형이라 불필요"라는 PRD 단정은 리스크. **성서공회 라이선스 협상 여부를 출시 게이트로 승격** — 미확보 시 근거구절 UX를 '장·절 참조(구절 미표시)'로 대체하는 폴백을 client·content와 사전 준비.
- QA 산출물: 위 3건의 **법무 사인오프 서명란**을 출시 게이트 체크리스트(20.13)에 포함.

| ANR율 | > 0.3% | 조사·차단 | 알림 |
| 콜드스타트 p90 회귀 | 기준 대비 +20% | 성능 조사 | 알림 |

| 광고 표시 실패율 | > 급증 임계 | 광고 킬 스위치 검토 | 알림 |
| 안티치트 이상탐지 큐 | 급증 | server·data 검토 | 알림 |

- 온콜: 단계적 롤아웃 중(특히 1%→20% 구간) 온콜 지정(ops).
- 릴리즈 헬스 대시보드: 버전별 크래시-프리·유지·결제·광고 지표 1화면(data 협업).

## 20.16 가정 / 미해결

(assumptions·openQuestions는 별도 필드에도 기재)

- 본 문서는 Flutter 단일 코드베이스·Firebase(Crashlytics/Performance/Remote Config/Test Lab)·AdMob·카카오 로그인 스택을 가정한다. 스택 변경 시 도구 매핑 재조정.
- 최소 사양(Android 8.0/iOS 14)은 출시 전 실기기 분포(data) 미확보 상태의 권고값이며 파일럿 텔레메트리로 확정한다.
- 성능·크래시 임계 수치는 업계 통상값 기반 권고이며, 파일럿 실측으로 재보정한다.
- 법무·저작권 항목은 QA가 '게이트로 검증'할 뿐 판단 주체는 legal이며, 사인오프 부재 시 출시 차단으로 간주한다.
- **크로스파트 단일화 대기 항목(RC 전 확정 필수)**: ① 텍스트스케일 결합 클램프 상한(현 design/ux 1.3·client 1.6·qa 종전 2.0) — 확정 주체 design(11.3.3), qa는 확정값에 골든/회귀 정렬(20.3.3); ② 오프라인 채점 모델(프리페치+큐 vs client 오프라인팩) — 안티치트 우선 시 오프라인팩 폐기(20.7.4); ③ F9 자동수정 가드레일(허용필드·편집거리·신뢰도, 특히 해설 자동수정 금지) 단일 표(20.6.4). 미확정 시 해당 게이트 항목은 No-Go.
