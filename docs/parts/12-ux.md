# 12. UX(사용자 경험)

> 한 줄 목적: 40~70대 기독교인이 도움 없이 새벽·저녁 습관에 얹어 성경 퀴즈를 풀고, 오탭·이탈·불신 없이 "우리 교회를 위해" 순위를 확인·공유하게 만드는, 큰 글씨·2단계·명예 정서 기반의 화면·플로우·마이크로카피 실행 규격.

## 12.1 정보구조(IA)

### 12.1.1 탭 3개 · 깊이 규칙
- **깊이 정의**: 탭(0단계) → 목록/메인(1단계) → 상세(2단계). **상세에서 더 들어가지 않는다**(PRD 2단계 초과 금지).
- **퀴즈·온보딩·구독결제·초대는 탭에 넣지 않고 전체화면 태스크(모달 플로우)** 로 띄운다 → 탭 3개를 유지하면서도 몰입 태스크는 자유롭게 구성.
- 모든 상세 화면 좌상단에 **[← 뒤로]** 텍스트 버튼(아이콘 단독 금지), 오른쪽 상단에 시스템 액션 최대 1개.

### 12.1.2 화면맵 (Screen Map)

```
[홈]  (기본 진입 탭)
 ├─ 오늘의 말씀 카드 (매일 1구절, QT 앵커)
 ├─ 출석 체크 위젯 (연속 N일)
 ├─ ▣ [퀴즈 시작]  ← 최상단·최대 CTA → (모달) 카테고리 선택 → 퀴즈 플로우
 ├─ (미등록 시) 교회 등록 배너
 └─ 맥락 넛지 배너 슬롯 1개 (F8 규칙, 일 1회)

[순위]
 ├─ 세그먼트 [ 교회 대항 | 개인 ]
 ├─ (교회 대항) 리그 필터 [개척|중형|대형|통합] → 교회 리스트
 │     └─ 교회 상세(2단계): 순위추이 · 기여자 TOP20 · 참여인원 · [응원하기 공유] · [정보가 틀렸나요?]
 └─ (개인) [전국|시도|우리교회] 서브탭 · 내 순위 상단 고정

[내정보]
 ├─ 프로필: 티어 심볼 · 배지 · 누적 포인트
 ├─ 출석 현황
 ├─ 오답노트  (무료: 최근 N개 / 프리미엄: 무제한)  → 오답 상세(2단계)
 ├─ 통계  (프리미엄: 카테고리별 정답률)
 ├─ [초대하기] → 초대 화면(2단계): 내 코드·유효초대 수·진행중·초대왕(v1.1)
 ├─ [말씀퀴즈 프리미엄] → 구독 화면(2단계)
 └─ [설정] → 설정 화면(2단계)
        ├─ 글자 크기 (보통/큰/아주 큰)
        ├─ 화면 (밝게/어둡게/시스템)
        ├─ 알림 (정보성/광고성/야간 수신 개별 토글)
        ├─ 계정 (연결된 카카오, 로그아웃, 회원 탈퇴)
        ├─ 개인정보·약관 (처리방침·이용약관·동의 이력[마케팅·야간·국외이전·B2B·종교 동의 상태 확인/변경]·데이터 열람/삭제 요청)
        └─ 고객센터 (FAQ · 1:1 문의 · 카카오 채널)
```

> **인터페이스(client/design)**: 탭바 높이 64pt, 아이콘 24pt + 라벨 14pt(아이콘 단독 금지). 홈은 앱 실행 시 항상 기본 탭.

## 12.2 중장년 UX 가이드라인 (기본값 = 중장년)

### 12.2.1 치수·간격 토큰 (client/design에 전달할 규격)

| 항목 | 값('보통' 기준) | 비고 |
|---|---|---|
| 문제 본문 폰트 | 20pt (최소 18pt) | PRD 본문 18pt 이상 |
| 선택지 라벨 폰트 | 20pt | |
| 주요 버튼 라벨 | 18pt | |
| 캡션/보조 텍스트 | 16pt (14pt 이하 금지 원칙) | |
| 선택지 버튼 높이 | **최소 56pt** | PRD 명시 |
| 일반 버튼 높이 | 최소 48pt | |
| 최소 터치 타깃 | 48×48pt (권장 56) | 오탭 방지 |
| 선택지 간 세로 간격 | **12pt 이상** | 인접 오탭 방지 |
| 화면 좌우 여백 | 20pt | |
| 라인 높이 | 1.4배 이상 | 가독성 |

- 글자크기 토글 3단계 배율: **보통 ×1.0 / 큰 ×1.15 / 아주 큰 ×1.3** (위 값에 곱). OS 동적폰트와의 **결합(OS×앱) 상한(클램프)은 design 단일 토큰 테이블을 단일 출처로 참조**하며, **본문 18pt·선택지 버튼 56pt 하한은 전 배율에서 유지**한다(client 클램프 구현·qa 골든 회귀 배율을 이 확정값에 정렬 — 현재 client 1.6/qa 2.0 간극은 design 확정 상한으로 통일). 아주 큰에서도 레이아웃이 깨지지 않도록 세로 스크롤 허용, 버튼 텍스트 줄바꿈 허용.

### 12.2.2 상호작용 원칙
1. **한 화면 = 한 주요 행동.** 주요 CTA는 화면당 1개, 화면 하단 고정 또는 엄지 도달 영역(하단 1/3).
2. **아이콘 단독 사용 금지.** 항상 텍스트 라벨 병기(예: 톱니 아이콘 옆 "설정").
3. **제스처 의존 금지.** 스와이프·롱프레스·핀치를 핵심 동작에 쓰지 않는다(모두 탭으로 대체 경로 제공).
4. **자동 전환 금지.** 채점 후 다음 문제로 자동 넘김 없음 — [다음 문제] 명시 탭. (오탭·놓침 방지)
5. **되돌리기 우선.** 비파괴 행동은 확인창 대신 실행 + [실행취소] 토스트(5초).

### 12.2.3 확인/취소 패턴 (파괴적 행동만 다이얼로그)

| 행동 | 확인 필요 | 다이얼로그 문구(예) | 버튼 배치 |
|---|---|---|---|
| 회원 탈퇴 | O(2단 확인) | "탈퇴하면 포인트·티어·연속 출석이 모두 사라져요." | [취소](기본) / [탈퇴하기](약한 강조) |
| 구독 해지 | O | "해지해도 이번 결제 기간까지는 이용할 수 있어요." | [계속 이용] / [해지 안내로] |
| 교회 변경 | O | "교회는 한 달에 한 번만 바꿀 수 있어요. 지금 바꿀까요?" | [취소] / [교회 바꾸기] |
| 로그아웃 | O | "다시 로그인하려면 카카오 인증이 필요해요." | [취소] / [로그아웃] |
| 신고 취소·출석 등 | X | — Undo 토스트로 처리 | — |

- **버튼 순서 고정**: 왼쪽 = 안전(취소/계속 이용), 오른쪽 = 파괴적 행동. 파괴 버튼은 빨간 채움 대신 외곽선/약한 강조(중장년 정서상 위압감 최소).
- 다이얼로그는 **2버튼 초과 금지**, 본문 2줄 이내.

> **의존성(qa)**: 오탭·다이얼로그 오조작 시나리오를 기기 매트릭스(저사양 안드로이드 포함) 회귀 대상에 포함.

## 12.3 핵심 사용자 플로우 (스텝 · 분기 · 이탈지점)

표기: **분기**는 화면 내 갈림길, **이탈지점**은 사용자가 떨어질 위험 + 대응.

### 12.3.1 온보딩 (첫 실행) — 최우선 이탈 방지 플로우

목표 순서: 로그인 → 동의 → 연령 확인 → 큰글씨 선택 → 난이도 진단 10문제(광고 없음) → 첫 티어 연출 → 교회 등록 유도(스킵 가능) → 알림 권한 → 홈.

| 스텝 | 화면/행동 | 분기 | 이탈지점 & 대응 |
|---|---|---|---|
| O1 | 스플래시 → 로그인. **[카카오로 시작하기]** 대형 버튼 단일(+iOS 심사용 Apple 로그인 하단 작게) | 카카오 미설치 → 카카오 웹 로그인 폴백 | 로그인 실패 시 "다시 한 번 눌러주세요" + 재시도. **가입 前 이탈 최다** → 화면에 가치 한 줄("무료로 성경 퀴즈 시작")만 노출, 약관은 다음 화면 |
| O2 | **동의 화면(1장)**: 필수(이용약관·개인정보처리방침), 선택(마케팅·야간 수신·국외이전 고지, **B2B/목회자·기관 제공(목적외) 제공 동의**). **종교(민감정보) 동의는 여기서 받지 않음** → 교회 등록 직전(12.3.3 C단계)에 선택 동의로 수집 | 필수(약관·개인정보) 미동의 → 진행 불가(비활성 CTA + 사유 안내). **선택·B2B 미동의는 진행 가능**(개인 퀴즈는 무동의로 정상 이용) | 동의 항목 과다 이탈 → 필수(약관·개인정보)만으로 진입 가능한 최소 경로 우선. 선택·B2B 항목은 시각적으로 구분·별도 라인, 각 항목 [자세히] 접이식. "전체 동의"는 선택 항목 편의로 제공(필수·선택 시각 분리) |
| O3 | **연령 확인**: 생년 또는 "만 14세 이상입니까?" | 만 14세 미만 → 법정대리인 동의 경로(v1 정책 확정 필요, openQuestion) 또는 이용 제한 안내 | 주일학교 아동 유입 리스크 → 미성년 실명 전국 노출 차단(닉네임 강제), 아동 맞춤형 광고 비활성 플래그 세팅 |
| O4 | **큰글씨 선택**: [보통/큰/아주 큰] 실시간 미리보기(같은 예시 문구가 크기별로 즉시 변화) | — | 스킵 가능하되 기본값 = '큰'. 되돌리기 쉬움(설정에서 언제든 변경) |
| O5 | **난이도 진단 10문제**(광고 없음, 즉시채점): 하단 진행바 "3/10" | 정답률 → 쉬움/보통/어려움 자동 배정 | **중간 이탈 방지**: 오답 비난 금지, "진단 중이라 점수는 안 깎여요" 안내, 5문항째 "절반 왔어요" 격려 |
| O6 | **첫 티어 연출**: '겨자씨' 획득 카드(축하 애니메이션, 모션 최소 설정 시 정적) | — | 성취감 앵커 — 여기서 "교회를 위해 겨자씨를 키워요" 문구로 다음 스텝 동기 부여 |
| O7 | **교회 등록 유도**(스킵 가능): [우리 교회 찾기] / [나중에 하기]. 등록을 실제 진행할 때만 종교·교회소속 민감정보 선택 동의 수집(스킵 시 미수집) | 스킵 → 홈 배너로 재유도 | 검색 부담 이탈 → "N만 명이 교회를 등록했어요" 사회적 증거, 스킵 명시 허용 |
| O8 | **알림 권한**(가치 설명 선행 화면 후 OS 프롬프트): "교회 순위가 바뀌면 알려드릴까요?" | 거부 → 인앱 배너로 대체 | OS 프롬프트 남발 금지(사전 설명 화면 1장 후 요청). ATT(iOS)는 별도 시점(첫 광고 直前) |
| O9 | 홈 진입 | — | 완료 |

- **온보딩 KPI 계측 포인트(data 연동)**: O1→O2→O5완료→O9 각 단계 전환율. 목표: 로그인→홈 완주율 ≥ 70%.
- **재진입 복구**: 중도 이탈 후 재실행 시 마지막 완료 스텝에서 이어가기.

### 12.3.2 퀴즈 코어 루프 (Core Loop)

진입: 홈 [퀴즈 시작] → 카테고리 선택 시트.

| 스텝 | 화면/행동 | 분기 | 이탈지점 & 대응 |
|---|---|---|---|
| Q0 | **카테고리 선택 바텀시트**: 구약/신약/인물/사건·지명/통합 랜덤(대형 카드 5개) | 통합 랜덤이 기본 추천(맨 위) | 선택 부담 → "아무거나 풀래요 = 통합 랜덤" 최상단 |

### 12.3.3 교회 검색·등록

진입: 온보딩 O7 / 홈 배너 / 순위 '우리 교회' 빈 상태.

| 스텝 | 화면/행동 | 분기 | 이탈지점 & 대응 |
|---|---|---|---|
| C1 | **교회명 검색창**(자동완성) | 결과 있음 → 후보 리스트 | 초성/오타 관대 검색, 최근 검색 노출 |
| C2 | **후보 리스트**: 교회명 + 지역 주소 + "N명 성도" 배지(사회적 증거). 동명 교회는 지역으로 구분 | 원하는 교회 없음 → [교회 직접 등록] 폴백 | 동명 교회 혼동 → 주소·행정동 병기 필수 |
| C3 | **선택 확인 + 종교 민감정보 선택 동의**: "○○교회(△△구)가 맞나요?" 화면에서 **'종교·교회소속 정보 수집·이용 동의(민감정보)' 별도 선택 체크** | 아니오 → 검색 복귀 / **동의 미체크 → 교회 등록만 비활성**(개인 퀴즈는 정상) | 잘못 선택 방지 확인 1회 + PIPA §23 별도 동의를 교회 기능 이용 시점에 수집 |
| C4 | **직접 등록(폴백)**: 교회명·주소·(선택)교단 → 검수 큐 제출 | 제출 → "확인 후 등록돼요(보통 N일)" 안내 | 즉시 반영 아님 안내로 기대치 관리. 임시로 '등록 대기' 상태 표시 |
| C5 | 등록 완료 → 순위 '우리 교회' 활성 | 교회 변경은 월 1회 제한(다이얼로그) | 변경 시 기존 주간 기여 이전 여부 = openQuestion(server) |
| C6 | **교회 정보 정정/클레임**(교회 상세 내 [정보가 틀렸나요?]): 원탭 사유(폐업/이전/개명/중복/대표자 정정) → ops 접수 큐 | — | 비인가 등록·병합/분립 대응의 최소 창구(v2 대시보드 前 임시) |

- **종교(민감정보) 동의 수집 원칙**: 온보딩 진입 게이트가 아니라 **교회 등록을 실제로 완료하는 시점(C3 직전)의 선택 동의**로 수집한다. 미동의 시 **교회 기능만 비활성, 개인 퀴즈는 무동의로 정상 이용**(legal 19.3/data 17.11.1/client 13.10과 정합).

> **의존성(server/ops)**: 검색은 자체 레코드 우선(장소검색 API 약관 리스크), 사전 시딩 verified 배지 표기. 클레임은 ops 수동 처리 큐.

## 12.4 접근성 (Accessibility)

### 12.4.1 목표 기준
- **대비**: 본문 WCAG AA 4.5:1, 대형 텍스트·아이콘 3:1 이상.
- **정보의 색 비의존**: 정답/오답을 색으로만 구분 금지 → **아이콘(체크/X) + 텍스트** 필수(색약 남성 8% 대응, D3). 오답 색은 웜 테라코타(#C7622D)를 쓰되 반드시 아이콘·텍스트와 3중 결합.
- **동적 폰트**: OS 글꼴 크기 설정 존중 + 앱 내 3단계 토글(×1.0/1.15/1.3). 둘의 **결합(OS×앱) 상한(클램프)은 design 단일 토큰 테이블을 단일 출처로 확정·참조**하며, 본문 18pt·선택지 56pt 하한을 전 배율에서 유지(client 클램프·qa 골든 회귀를 동일 값에 정렬).
- **스크린리더**(TalkBack/VoiceOver): 모든 인터랙티브 요소 라벨, 논리적 포커스 순서, 선택지 그룹핑, **채점 결과 라이브리전 announce**("정답입니다. 다음 문제 버튼.").
- **모션 최소**: OS '동작 줄이기' 존중 → 티어 연출·콤보·전환 애니메이션을 정적 대체(페이드만).
- **햅틱**: 정답/오답 구분 햅틱(서버 응답 후 발생, 설정에서 끄기 가능).
- **다크/야간 모드**(D4): 새벽 사용 맥락, 명도 대비 별도 검증.

### 12.4.2 접근성 체크리스트 (qa 회귀 대상)
- [ ] 모든 버튼 터치 타깃 ≥ 48pt, 선택지 ≥ 56pt, 간격 ≥ 12pt
- [ ] '아주 큰' 글씨(design 확정 결합 상한)에서 텍스트 잘림·겹침 없음(스크롤/줄바꿈 허용, 본문 18pt·선택지 56pt 하한 유지)
- [ ] 정답/오답이 흑백 화면에서도 구분됨(아이콘·텍스트)
- [ ] TalkBack/VoiceOver로 온보딩→퀴즈 1회 완주 가능
- [ ] 다크모드 전 화면 대비 통과
- [ ] '동작 줄이기' 시 애니메이션 대체 동작
- [ ] 색상 팔레트 대비비 자동 검증(design 토큰 단계)

> **의존성(design)**: 위 토큰·팔레트(오답=웜 테라코타 토큰, 결합 배율 상한 단일 테이블)를 디자인 시스템에 반영. **의존성(client)**: Flutter Semantics 트리·Dynamic Type·라이브리전 구현.

## 12.5 마이크로카피 원칙 & 예시

### 12.5.1 원칙 (Voice & Tone)
1. **존댓말 · 따뜻함 · 존중.** 사용자를 신앙 동역자로 대한다.
2. **격려 우선, 비난 금지.** 오답에도 위로.
3. **짧고 쉬운 말.** 전문용어·영어 배제('랭킹'→'순위', '프로필'은 관용 허용).
4. **교리 중립 · 사실 기반.** 특정 교단·해석 표현 회피("하나님/하느님" 표기 통일은 content/legal 협의).
5. **명예 정서.** 현금·보상 대신 "기여·열매·세워감" 어휘.

## 12.7 상태 디자인 (빈/로딩/오류/오프라인)

| 상태 | 화면 | 사양 |

## 12.8 온보딩 이탈 방지 설계 (종합)

1. **가치 먼저, 마찰 나중**: 로그인 화면은 버튼 1개 + 한 줄 가치. 약관·연령은 그 다음 화면.
2. **동의 이탈 완화**: 1화면 통합, **필수(약관·개인정보)만 진입 게이트**. 종교 민감정보 동의는 온보딩에서 받지 않고 **교회 등록 직전 선택 동의로 분리**(PIPA 강요·번들 금지, D8). **B2B(목적외) 동의는 선택 항목으로 노출하되 거부해도 이용 가능**(D10).
3. **광고 없는 진단**: 첫 10문제는 광고·포인트 압박 제거, 성취(첫 티어)로 마무리.
4. **교회 등록은 스킵 허용 + 재유도**: 강제 시 이탈 > 이득. 홈 배너·순위 빈 상태에서 반복 노출.
5. **권한 요청 지연**: 알림은 사전 설명 후, ATT는 첫 광고 前으로 분리.
6. **중도 이탈 복구**: 마지막 완료 스텝 저장·이어가기.
7. **완주율 목표 ≥ 70%**, 단계별 퍼널 계측(data).

## 12.11 사용성 테스트 계획 (중장년)

### 12.11.1 모집
- **대상**: 45~70대 기독교인, 스마트폰 자가 사용 가능 수준으로 스크리닝(카톡 사용·앱 설치 경험 유무 문항). P1(권사형) 5명, P2(집사형) 3명 균형.

### 12.11.2 과업 시나리오 (관찰 지표: 성공/실패·소요시간·이탈지점·오탭 횟수·발화)
1. 처음 실행해 **로그인하고 첫 퀴즈 10문제를 풀어보세요**.(온보딩 완주)
2. **우리 교회를 찾아 등록해 보세요**.(검색·동명 구분)
3. **우리 교회 순위와, 이번 주 1등 교회를 확인해 보세요**.(리더보드 탐색)
4. 방금 푼 문제 중 **틀린 것 같은 문제를 신고해 보세요**.(원탭 신고)
5. **친구(구역 식구)에게 초대장을 보내보세요**.(1탭 공유)
6. **글씨를 더 크게 바꿔보세요**.(접근성 토글 발견성)
7. (선택) **광고 없이 보는 방법을 찾아보세요**.(구독 진입 이해)

### 12.11.3 지표 & 합격선
| 지표 | 측정 | 합격선 |
|---|---|---|
| 과업 성공률 | 과업별 무도움 완수 | ≥ 80% |
| 온보딩 완주 시간 | O1→Q1 | ≤ 4분 |

| "도움 없이 할 수 있었다" | 자기보고 | ≥ 80% |

### 12.11.4 운영
- 방식: 대면 우선(중장년 원격 난이도), Think-aloud + 화면 녹화(동의). 진행자 스크립트 표준화.

## 12.13 열린 결정 (UX 관점 권고 포함)
- **주간 리셋 요일**(월 00시 vs 주일 저녁): UX상 '주일 예배 후 성적표' 정서가 강하나 결산 카드는 월요일 아침이 자연스러움 → **파일럿 A/B 권고**(server/data).
- **오답 색·톤(확정)**: 신호 적색 단독 금지, **웜 테라코타(#C7622D) + X 아이콘 + 격려 문구 3중**으로 확정(design 토큰·branding 팔레트 정합, D3). 정서 반응은 파일럿에서 모니터링.
- **코어 응답 방식(확정)**: PRD F1 즉시채점을 기본으로 확정(선택 즉시 제출 → 서버 응답 후 정오 표시). 오탭 방지용 '확인 후 제출'은 설정 옵트인(D2). 안티치트 1.5초 룰은 문제 표시→탭 latency로 측정.
- **글자크기 결합(확정)**: 앱 3단계(×1.0/1.15/1.3)를 OS 동적폰트에 곱연산, **결합(OS×앱) 상한은 design 단일 토큰으로 확정·참조**(본문 18pt·선택지 56pt 하한 유지). qa 골든·client 클램프를 동일 값에 정렬(현재 qa 2.0/client 1.6 간극 제거).
