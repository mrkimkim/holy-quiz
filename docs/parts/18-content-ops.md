## 18.1 출제 철학의 운영화 — "무엇을 물어도 되는가"

PRD 제5장 최상위 원칙("성경의 '내용'을 묻는다, 자구 암송 금지, 사실 기반 한정, 교리·해석 출제 금지")을 **검수자가 기계적으로 판정할 수 있는 규칙**으로 내린다.

### 18.1.1 허용/금지 판정표 (검수 1차 게이트)

| 구분 | 허용(ALLOW) | 금지(BLOCK) | 예시 |
|---|---|---|---|
| 사실 vs 해석 | 성경 텍스트 내부의 관찰 가능한 사실 | 사건의 신학적 '의미'·교훈·적용 | ✅ "다윗이 물리친 블레셋 장수는?"(골리앗) / ❌ "다윗과 골리앗 이야기가 주는 교훈은?" |
| 내용 vs 자구 | 줄거리·인물·장소·순서·숫자 | 특정 절의 단어 빈칸 암송 | ✅ "요셉이 팔려간 나라는?"(애굽) / ❌ "요 3:16의 빈칸: 하나님이 세상을 이처럼 ___하사" |
| 사실 vs 교리 | 교단 무관 성경 서술 | 교단별 답이 갈리는 신학 명제 | ✅ "예수님이 세례 받으신 강은?"(요단강) / ❌ "유아세례는 성경적인가?" |
| 확정 vs 논쟁 | 본문에 명시된 것 | 학계/교단 미확정 사안 | ✅ "바울의 회심 장소로 가던 도시는?"(다메섹) / ❌ "요한계시록의 천년왕국은 문자적인가 상징적인가?" |

### 18.1.2 교단 민감 주제 블랙리스트 (자동 리젝 사유 태그)

한국 개신교 주요 교단(예장통합·합동·고신, 기감, 기장, 기침, 성결, 순복음/하나님의성회)에서 답이 갈리거나 정서를 자극하는 주제는 **출제 금지**. 검수자·LLM 프롬프트에 동일 목록을 주입한다.

- 세례 vs 침례(방식·유아세례 정당성)
- 종말론(전천년/후천년/무천년, 휴거 시점, 천년왕국 해석)
- 예정론 vs 자유의지, 구원의 확신·상실 가능성
- 방언·신유·예언 등 은사 지속/중지론
- 창조 연대(문자적 6일 vs 유신진화), 지구 나이
- 성령세례/성령충만의 시점·표징
- 안식일 vs 주일, 십일조의 강제성
- 성찬의 실재(화체·공재·기념)
- 여성 안수, 직분 체계의 성경적 근거
- 외경/제2경전의 정경성(개신교 66권 외 포함 여부)
- 성경 무오/유오, 특정 사본·번역본 우월성

> **주의(중장년·교회 정서):** 인물·직분을 상징으로 쓰는 것도 회피(F2 티어가 이미 '성경 속 사물'을 채택한 이유와 동일). 문항 소재로 특정 교단 창시자·현대 인물·교단명이 등장하면 자동 리젝.

### 18.1.3 오답(distractor) 설계 원칙

찍기 정답률 25%가 명예 시스템 변별력의 하한이므로(F1), 오답은 "매력적이되 함정이 아니어야" 한다.

- **동일 카테고리 내 근접 오답:** 정답이 인물이면 오답도 같은 시대·같은 책의 인물(예: 정답 '아브라함' → 오답 '이삭/야곱/롯')
- **금지:** 명백히 틀린 상식(예: 정답 '가나' → 오답 '서울')은 정답률을 인위적으로 올려 변별력 파괴
- **금지:** '위 전부/정답 없음' 형태, 이중 부정, 두 개가 동시에 맞는 모호 오답
- 4지선다 선택지 길이 편차 최소화(가장 긴 것이 정답인 패턴 방지 → 매크로/추측 방어)

## 18.2 문제 스키마 / 메타데이터

콘텐츠 DB의 단일 진실원(single source of truth) 스키마. **server 파트가 이 스키마로 테이블·서빙 API·통계 집계를 구현**한다(§18.11 인터페이스).

### 18.2.1 문항 JSON 스키마 (v1)

```json
{
  "id": "Q-NT-000123",
  "schema_version": 1,
  "testament": "NT",                 // OT | NT  (D3 1차축)
  "topic_tags": ["person", "miracle"], // person|event|place|number|order|object
  "difficulty": "normal",            // easy | normal | hard (초기 저자추정)
  "difficulty_calibrated": null,     // 실측 재라벨 후 채워짐(§18.7)
  "question": "예수님께서 물로 포도주를 만드신 첫 표적이 일어난 곳은?",
  "options": ["가나", "가버나움", "예루살렘", "벳새다"],
  "answer_index": 0,
  "explanation": "가나의 혼인 잔치에서 첫 표적을 행하셨습니다.",
  "ref": { "book": "요한복음", "chapter": 2, "verse_start": 1, "verse_end": 11 },
  "ref_text": null,                  // 라이선스 게이트 필드(D2). 미확보 시 null 유지
  "ref_text_license": "unlicensed",  // unlicensed | krv_revised(개역개정)
  "status": "active",                // 아래 라이프사이클 값
  "source": {
    "generator": "claude-opus-4-8",
    "batch_id": "GEN-2026-W28-03",
    "created_at": "2026-07-12T09:00:00+09:00"
  },
  "review": {
    "theology_reviewer": "REV-001",
    "reviewed_at": "2026-07-14T11:00:00+09:00",
    "editor": "ED-002",
    "verdict_notes": "교리중립 확인"
  },
  "stats": {                          // server가 집계·기입(§18.11)
    "served": 0, "correct": 0, "correct_rate": null,
    "distractor_pick": [0,0,0,0],
    "report_count": 0, "last_served_at": null
  },

```

### 18.2.2 필드 규칙

| 필드 | 규칙·검증 | 담당 |
|---|---|---|
| `question` | ≤ 60자(권장 45), 물음표로 종결, 존칭 통일(하십시오체) | content |
| `options` | 정확히 4개, 각 ≤ 18자(권장 12), 중복 금지 | content |
| `answer_index` | 0~3, 정확히 1개 | content |
| `ref` | **필수**(PRD "모든 문제 근거구절 필수"). 개역개정 책명 표준표기 | content |
| `ref_text` | 라이선스 확보 전 `null`. 확보 후 배치 백필(D2) | content×legal |
| `difficulty` | 온보딩 진단·출제 배정용 | content→client |
| `stats` | 읽기 전용(콘텐츠팀), 쓰기=server | server |

> **저작권 디커플링(갭[high] 해소):** `ref`(주소)는 사실 정보라 저작권 대상이 아니므로 항상 저장·표시 가능하다. verbatim 본문(`ref_text`)만 라이선스에 종속시켜, 성서공회 협상이 지연돼도 앱은 "근거: 요한복음 2:1-11"까지는 항상 보여주고 본문만 숨긴다. F1(정답 시 근거구절) UX는 legal/ux와 협의해 degrade 모드를 미리 설계(§18.9, §18.11). verbatim 라이선스 대상은 오늘의말씀·F1 근거구절·F9 원문 **3개 전부**임에 유의(§18.10.1).

## 18.3 초기 3,000문항 확보 계획 (난이도 4:4:2)

### 18.3.1 물량·구성 목표

| 난이도 | 비율 | 문항 수 | 검수 통과 목표 위해 생성할 초안 수(리젝 30% 가정) |
|---|---|---|---|
| 쉬움 | 40% | 1,200 | ~1,560 |
| 보통 | 40% | 1,200 | ~1,560 |
| 어려움 | 20% | 600 | ~860 |
| **합계** | 100% | **3,000** | **~3,980** |

카테고리 분포 권고(2차 태그 기준, 중첩 허용): 구약 55% / 신약 45%; 인물 35% / 사건 30% / 지명 15% / 숫자·순서 20%. 구약 편중은 서사 풍부성 때문이나, 신약도 최소 40% 확보(P1/P2가 복음서·사도행전에 친숙).

### 18.3.2 생산 일정 (T = 파일럿 킥오프 기준, 파일럿 전 콘텐츠 준비 완료가 목표)

MVP는 T+10주지만 **비공개 파일럿(정식출시 2~4주 전)에 콘텐츠가 이미 있어야** 밸런스/파밍을 검증할 수 있다. 따라서 콘텐츠 준비 데드라인은 **파일럿 투입 시점(T+6주)** 으로 확정한다. org(§22.3.2)의 'T+10주(3,000÷10주)' 산정은 파일럿 선(先)투입을 누락한 값이므로 **T+6주로 정렬**하되, 처리량은 org의 **신학 검수 풀 3인(리드1+교차검수2, 파트타임 주20h) + 편집보조 1인**으로 충족한다(§18.3.3). content·org 공통 게이트 = '콘텐츠 재고 2주(=14일) 버퍼' KPI(§18.11.2).

| 주차 | 작업 | 산출·게이트 |
|---|---|---|
| W0 | 파이프라인 셋업: 프롬프트 확정, 블랙리스트 주입, 검수 rubric·계약, DB 스키마 프리즈 | 골든셋 50문항 수기 작성(생성 품질 기준선) |
| W1 | LLM 초안 1차 배치 1,000건 생성 → 자동검증 → 검수 투입 | 검수 리드타임 실측 |
| W2 | 초안 2차 1,000 + W1 검수 승인분 배포 | 승인 400~600 |
| W3 | 초안 3차 1,000 + 검수 | 누적 승인 ~1,200 |
| W4 | 초안 4차 980 + 검수 | 누적 ~1,900 |
| W5 | 검수 소화 + 재작성(반려분 재생성) | 누적 ~2,600 |
| W6 | 최종 검수·밸런스 조정(난이도 4:4:2 맞춤), **파일럿 투입** | **3,000 active** |
| W7~ | 파일럿 실측 → 난이도 재라벨 준비(§18.7) | 캘리브레이션 데이터 축적 |

### 18.3.3 검수 처리량(throughput) 산정과 병목 해소

**신학 검수자 1인 처리량 가정:** 자동검증을 통과한 정제된 4지선다 1문항 검수 = 평균 3~4분(질문·정답·4선택지·근거구절·교리중립 확인). 파트타임(주 20h) 기준 지속 가능 속도 ≈ **250~300문항/주/인**.

- 필요 처리량: 3,980 초안 검수 ÷ 6주 = **약 660문항/주**(≈133/영업일). **1인 단독은 초과·번아웃·품질저하 위험(갭[high]).**
- **해소책(D5) — org §22.3.2와 동일 산정:**
  1. **신학 검수 풀 3인(리드1+교차검수2, 파트타임):** 풀 처리 능력 ≈ 750~900/주 > 필요 660/주 → 여유 확보. 교차검수 2인이 곧 SPOF 보험이므로 별도 백업 온콜 불요.
  2. **국문 편집 보조 1인 선(先) 처리:** 오타·문장·형식·중복·길이제약을 신학자 앞단에서 걸러, 신학자는 교리·사실만 판정 → 유효 처리량 추가 상향.
  3. **LLM 자동검증으로 명백한 불량 사전 제거**(§18.6): 검수 큐에 들어가는 물량 자체를 20~30% 감축.
  4. **샘플 기반 QA:** 편집보조 통과분 중 10% 무작위를 신학자가 교차검증해 품질 하한 유지.

## 18.4 월 500+ 증분 운영 파이프라인

정상 운영 시 매월 신규 문항을 4단계로 흘린다: **LLM 초안 → 사실정합 자동검증 → 신학전공자 검수 → 배포.**

```
[1] 생성          [2] 자동검증(LLM+규칙)      [3] 인간검수            [4] 배포
Opus 4.8 배치  →  Haiku 4.5 사실선별 +     →  편집보조→신학자      →  status:active
(주 1회, 배치별      규칙검사(길이/중복/           (반려→[1] 재생성)        DB 반영 + stats 초기화
 배치ID 부여)         블랙리스트/스키마)                                    → server 서빙 대상 편입
```

### 18.4.1 단계별 규격

| 단계 | 도구/모델 | 입력 | 출력·게이트 | SLA |
|---|---|---|---|---|
| 1 생성 | `claude-opus-4-8`, Batch API | 카테고리·난이도 쿼터, 블랙리스트, 골든셋 예시(few-shot), 표기 규칙 | 스키마 준수 JSON 초안 N건 | 배치당 24h |
| 2 자동검증 | `claude-haiku-4-5`(사실체크) + 결정적 규칙엔진 | 초안 + `ref` | 통과/의심/자동리젝 3분류 | 배치당 24h |
| 3 검수 | 편집보조→신학자(+교차검수) | 통과·의심 문항 | 승인/수정/반려 | 문항 검수 72h 내 |
| 4 배포 | server 배치 인입 | 승인 문항 | `active`, stats 초기화 | 승인 즉시 다음 배포창 |

### 18.4.2 소진 방어(갭[high] 해소) — 콘텐츠 런웨이 관리

헤비유저(P2) 100문항/일 소비. F1 규칙상 재출제 20%·최근정답 하향이 있어 **실효 신규 소비 ≈ 80/일**. 500/월 증분은 신규 소비를 못 따라간다.

**권고 운영:**
- **런칭 후 3개월 프론트로드:** 월 1,000~1,500 증분(생성비용은 미미, §18.10). 이후 500+/월 정착.
- **런웨이 KPI(신설):** 세그먼트별 `미노출 신규문항 재고 ÷ 일평균 신규소비 ≥ 14일(=2주 버퍼)`. 14일 밑으로 떨어지면 생성 배치 증량 트리거(data 파트 대시보드 연동). **초기 3,000 확보 단계에도 동일 KPI를 content·org 공통 게이트로 사용(§18.3.2).**
- **재출제 UX 완충:** 30일+ 경과 재출제는 중장년에게 사실상 신규처럼 체감. F1 재출제 스케줄과 협의해 "최근 14일 내 정답 문항은 재출제 제외" 규칙 반영.

## 18.5 신학 검수 풀(외주 3인) 운영·가이드라인·품질 SLA

### 18.5.1 자격·계약

- **자격:** 신학대학원(M.Div 이상) 또는 신학 전공 학사+실무. **특정 교단 편향이 드러나지 않는 중립성**이 핵심 채용 기준(면접 시 §18.1.2 블랙리스트로 스크리닝 테스트).
- **구성(org §22.3.2 정렬):** 리드 1인 + 교차검수 2인(총 3인), 파트타임(주 20h) 기준. 교차검수 2인이 상호 SPOF 보험을 겸한다.
- **계약형태:** 월 정액(고정 처리량 SLA 포함) 또는 문항 단가.
- **SPOF 보험:** rubric·판정 로그를 문서화해 이전(transfer) 가능하게 유지(인력 이탈 대비).

### 18.5.2 검수 판정 rubric (문항당 체크리스트)

1. [ ] **사실 정확성:** 정답이 `ref` 본문과 일치하는가?
2. [ ] **교리 중립:** §18.1.2 블랙리스트 해당 없는가?
3. [ ] **정답 유일성:** 오답 4개 중 정답 후보가 하나뿐인가?
4. [ ] **오답 적정성:** 오답이 매력적이되 함정/이중정답이 아닌가?
5. [ ] **표기 표준:** 개역개정 책명·인명·지명·숫자표기 준수(§18.8)?
6. [ ] **형식:** 질문/선택지 길이 제한, 존칭 통일?
7. [ ] **근거구절 정합:** `ref`가 실제로 정답을 뒷받침하는가?

→ **판정 4택:** 승인 / 수정후승인(경미) / 반려(재생성) / 보류(추가확인 필요). 판정과 사유를 로그에 남겨 F9 LLM 프롬프트·재학습 근거로 활용.

### 18.5.3 품질 SLA

| 지표 | 목표 | 미달 시 |
|---|---|---|
| 검수 처리 리드타임 | 문항 인입 후 72h | 교차검수자 투입 |
| 샘플 QA 오류율(교차검증) | ≤ 2% | rubric 재교육 |
| 배포 후 신학오류 신고 채택율(§18.9) | ≤ 0.3% (신고 1천건당 3건 이하) | 근본원인 리뷰 |

## 18.6 사실정합 자동검증 (파이프라인 2단계 상세)

인간 검수 앞단에서 **결정적 규칙 + LLM 사실선별**로 물량을 줄이고 명백한 불량을 차단.

### 18.6.1 결정적 규칙엔진(코드, LLM 불필요)

- 스키마 유효성(필드·타입·`answer_index` 범위)
- 길이 제약(질문 60자·선택지 18자 초과 → 리젝)
- 선택지 중복·정답 중복 검사
- 블랙리스트 키워드 매칭(세례/침례/천년왕국/예정 등 → 리젝 또는 보류)
- 중복 문항 탐지(질문 정규화 후 유사도 임계 ≥ 0.9 → 보류)
- `ref` 책명이 개역개정 66권 표준표기인지

### 18.6.2 LLM 사실선별(`claude-haiku-4-5`, Batch API)

Haiku에 문항+근거구절 주소를 주고 "정답이 성경 사실과 부합하는지" 저비용 1차 스크린. 의심 판정은 신학자 큐로 우선 라우팅. Haiku는 대량·저가·고속(입력 $1/출력 $5 per 1M)이라 이 단계에 최적.

## 18.7 난이도 캘리브레이션 (정답률 기반 재분류)

### 18.7.1 콜드스타트 문제(갭[low] 해소)

초기 4:4:2와 온보딩 10문제 배정은 정답률 데이터 없는 **저자 추정**이다. 출시 후 실측 재라벨 루프가 없으면 배정 오류가 고착된다.

### 18.7.2 재분류 규칙 (월 1회 배치, data 파트와 공동)

- **최소 표본:** `served ≥ 100` 문항만 재라벨 대상.
- **v1 지표 = raw 정답률(단일 지표 통일):** 격리 트리거(§18.9.2)·난이도 재라벨·server 통계 집계·data(§17.14)가 모두 **raw `correct_rate`** 를 공유한다. 정규화(응시자 실력 보정, IRT-lite) 지표는 개인 실력 추정 표본이 충분히 쌓이는 **v1.1에서 도입**(원 정답률의 실력 편중 왜곡 보정)하되, v1 콜드스타트 구간에서는 표본 부족으로 raw를 확정 지표로 사용한다. server는 집계 필드가 raw `correct_rate`를 산출하도록 정렬.
- **밴드(raw 정답률, data §17.14와 정렬. 초기값, 파일럿으로 튜닝):**

| 재라벨 난이도 | raw 정답률 |
|---|---|
| 쉬움 | > 0.80 |
| 보통 | 0.40 ~ 0.80 |
| 어려움 | < 0.40 |

- **건전성 플래그:** 정답률 > 0.98(너무 쉬움→변별력 없음, 오답 재설계 검토) / < 0.15 & `served ≥ 50`(오류 의심 → **F9 자동격리 트리거**, §18.9.2).
- 재라벨 결과는 `difficulty_calibrated`에 기록(원 `difficulty`는 감사용으로 보존). 온보딩 10문제 진단 배점도 이 데이터로 재튜닝.

## 18.8 표기 표준 (개역개정)

문항·해설·근거구절·오늘의말씀 전부 **개역개정** 통일(D1). 검수 체크리스트 5번과 연동.

| 항목 | 규칙 | 예 |
|---|---|---|
| 책명 | 개역개정 정식 명칭 | 창세기, 출애굽기, 사무엘상, 데살로니가전서 |
| 구절 표기(UI) | `책 장:절` 약칭 | 요 3:16, 창 1:1-3 |
| 인명·지명 | 개역개정 표기 | 여호수아, 웃시야, 다메섹, 가버나움 |
| 숫자 | 문맥상 아라비아 숫자, 서수는 한글 허용 | "40일", "열두 제자" |
| 문체 | 질문·해설 **하십시오체** 통일 | "…한 곳은?" / "…행하셨습니다." |
| 금지 | 다른 번역본 표기 혼용(새번역·개역한글) | ✕ "여리고"/"예리고" 혼용 |

## 18.9 F9 자동검증기 설계 (오류신고·자동격리·LLM 판정·검수·배포)

신뢰 인프라의 핵심. 흐름: **신고/이상탐지 → 자동격리 → LLM 검증기 판정(4분기) → 처리(오타 자동수정/정답오류 검수대기/보류 인간검수) → 배포·롤백.**

### 18.9.1 신고 수집

- 해설 화면 상시 신고 버튼(F9). 원탭 사유: **정답틀림 / 근거구절다름 / 오타 / 모호 / 기타**.
- 동일 사용자 중복 신고는 1건으로 dedupe. 신고에 사용자·문항버전·사유·타임스탬프 기록.

### 18.9.2 자동격리 규칙 (server가 실시간 판정, 콘텐츠팀이 규칙 소유)

문항을 **즉시 서빙 중단**(`status: quarantined`)하는 트리거:

| 트리거 | 임계값 | 근거 |
|---|---|---|
| 신고 누적 | 서로 다른 사용자 **3건** | PRD F9 |
| 정답률 이상치 | `served ≥ 50` & **raw 정답률(`correct_rate`) < 15%** | PRD F9. server(§14.11.1)·ops(§21.3.1) 동일 지표 정렬 |
| 특정 오답 쏠림 | 한 오답 선택률이 정답 선택률을 초과(오답이 실제 정답 의심) | PRD F9 |

> 이상패턴 검토 큐(F3/F8 부정방지와 동일 인프라)에 연동. 격리는 리더보드 공정성 보호를 위해 **판정 전이라도 즉시** 실행. 격리·재라벨 모두 **raw 정답률**을 단일 지표로 사용(정규화는 v1.1, §18.7.2).

### 18.9.3 LLM 검증기 — 입력 구성

격리 문항에 대해 검증기 LLM(`claude-opus-4-8`)에 다음을 **구조화 입력**으로 제공:

1. 문항 전체(질문·4선택지·현재 정답·해설)
2. 근거구절 **주소 + 원문**(성서공회 라이선스 확보 시 verbatim; 미확보 시 주소만 → 검증기가 web 없이 내부지식으로 판정하되 신뢰도 하향)
3. 신고 사유 집계(사유별 건수)
4. 정답률·오답 분포 통계
5. §18.1.2 교단 블랙리스트, §18.8 표기 규칙(판정 기준으로)

### 18.9.4 검증기 프롬프트·출력 규격

- **모델:** `claude-opus-4-8`, `thinking: {type: "adaptive"}`(교리·사실 판단은 추론 필요), 구조화 출력 `output_config.format`(json_schema)로 4분기 강제.
- **시스템 프롬프트 핵심:** "당신은 교단 중립적 성경 사실 검증관이다. 개역개정 기준. 교리 해석 판단 금지, 사실·표기·정답 정합만 판정."
- **출력 스키마:**

```json
{
  "verdict": "normal | typo | answer_error | uncertain",
  "confidence": 0.0,                 // 0~1
  "reason": "판정 근거 1~3문장",
  "suggested_fix": {                 // typo/answer_error일 때만
    "field": "question | explanation | options | answer_index",
    "before": "...",
    "after": "...",
    "edit_distance": 0
  }
}
```

- **오탐 저감(무인배포 안전, 갭[medium] 해소):** 자동수정 후보(`typo`)는 **자기일관성 3회 샘플 또는 2모델 합의**(예: Opus 4.8 + Sonnet 5) — **판정·수정안이 전부 일치할 때만** 자동수정 자격 부여. 불일치 시 인간 검수로.

### 18.9.5 판정 4분기별 처리

| 판정 | 신뢰도 | 처리 | 배포 |
|---|---|---|---|
| **정상(normal)** | ≥ 0.9 | 기각, 자동 복귀 + 로그 | `active` 자동 복귀 |
| **오타(typo)** | **≥ 0.95** & 화이트리스트 충족(§18.9.6) | **자동수정 후 즉시 복귀**(지문만, 일 20건 상한) | 무인 배포(정답·해설·선택지·근거 불변) |
| **정답오류(answer_error)** | 무관 | 수정안 생성 → **검수 승인 대기(무인배포 금지)** | 인간 승인 후 |
| **보류(uncertain) / 저신뢰(<0.7)** | — | **인간 검수** | 검수 후 |

### 18.9.6 무인배포 허용 조건 (오타 자동수정 화이트리스트 — content·server·ops·qa 단일 규격)

정상 문항 훼손(갭[medium]) 방지를 위해 **아래 단일 표의 전 조건 AND 충족** 시에만 무인 배포한다. 파트별로 어긋났던 파라미터(허용 필드·편집거리·신뢰도)를 하나로 프리즈하며, **'해설(explanation) 자동수정 불허'를 확정**(안전 우선; ops §21.3.1·qa §20.6.4의 금지 방침과 정렬)한다.

| 파라미터 | 확정값 |
|---|---|
| 허용 필드 | **`question`(지문)만** — `explanation`·`options`·`answer_index`·`ref` 전부 불변 |
| 변경 유형 | 조사·맞춤법·띄어쓰기·명백한 오탈자(의미 변경 없음) |
| 편집거리 | **≤ 2자** |
| 최소 신뢰도 | **≥ 0.95** |
| 모델 합의 | 자기일관성 3회 또는 2모델 합의(판정·수정안 완전 일치, §18.9.4) |
| diff 가드 | `answer_index`·`options`·`ref`·`explanation` 바이트 불변을 코드로 재검증(불변 아니면 강제 인간검수) |
| 일 상한 | **20건/일** |
| 관찰창 | **48h**(재신고·정답률 급변 감시, §18.9.8) |
| 감사로그 | 필수 기록(§18.9.8) |

> LLM 검증기 고도화는 v1.1이나, **이 무인배포 규칙은 배포 게이트 전 프리즈**하고 qa 금지 골든셋(§20.6.4)에 반영해 회귀를 방지한다.

### 18.9.7 SLA

| 단계 | SLA |
|---|---|
| 격리 | 트리거 즉시 |
| LLM 자동판정 | 24h |
| 검수 승인(정답오류·보류) | 72h |

### 18.9.8 자동 롤백 & 감사로그

- **자동 롤백 트리거(관찰창 48h):** 자동수정 배포 후 48h 내 (a) 동일 문항 재신고 발생 or (b) 정답률 급변(±20%p) → 즉시 이전 버전 복원 + 인간 검수 강제.
- **감사로그 필수 필드:** `문항ID·이전버전·이후버전·판정·신뢰도·수정안·편집거리·모델버전·배치ID·자동/수동 여부·타임스탬프·롤백여부`. server가 append-only 저장(수정 불가), 콘텐츠팀·qa가 열람.

### 18.9.9 신고자 보상 (F2/monetization 연동)

- 채택 시: 푸시 알림 + **파수꾼 카운터 적립**. 신고 보상은 **랭킹·명예 티어와 완전 분리된 별도 '신뢰기여' 카운터**로만 집계한다(초대 보상 분리 방식과 동일). monetization '명예 불가침' 준수 및 어뷰징(다작 신고로 개인·교회 순위를 밀어올리는 경로) 차단을 위한 **확정 규칙(option b)**.
  - **server 인터페이스(§14.11.4/§14.8.2 정렬):** `point_ledger`에 `entry_type=report_reward`(week_id 포함)를 남기더라도, **티어 산정·주간 개인 리더보드·주간 교회점수(상위20 합산) 집계에서 전부 제외**한다(아웃박스 롤업에서 `report_reward` 명시적 필터). 원장 레코드는 감사·표시용으로만 보존.
- 마일스톤 배지: **파수꾼(채택 3회) / 성경지킴이(채택 10회)**.
- 월간 리포트(신고→처리 결과 요약)로 신뢰 루프 강화.

## 18.10 오늘의 말씀 운영·번역본·저작권 (오픈Q#6, 갭[high])

### 18.10.1 결정 권고

- **번역본:** **개역개정으로 통일**(D2b) — PRD·design(§11.8 슬롯)의 "v1 개역한글"을 뒤집기 권고. content §18.8 개역개정 표기 통일 원칙과 일원화(퀴즈 표기=오늘의말씀 번역본).
  - 근거: **개역한글(1961)도 대한성서공회 저작권 보호 저작물**이라 개역한글을 써도 라이선스를 회피할 수 없음(저작권 지위 불명확·분쟁 소지) / 개역개정은 현재 예장 계열 예배 표준본으로 45세+ 성도 친숙 / 퀴즈 표기 표준과 이원화 방지.
- **저작권(협상 범위 단일화):** verbatim 표시 대상 = **오늘의말씀 전체 + F1 근거구절 + F9 검증 원문** 3개 전부이며, 축자 복제·전송이므로 **성서공회 라이선스가 필수**(legal 블로커). PRD의 "오늘의말씀만 법률확인 / 퀴즈는 라이선스 불필요" 축소 인식은 오판(갭[high]) → **3개 전부를 단일 협상 범위**로 확정. server(§14.20)·content(D2)의 `ref_text` 분리 게이트와 정렬.
- **성서공회 라이선스는 출시 차단(blocking) 법무 의존성**으로 격상. 협상 오너=legal(§18.11).

### 18.10.2 라이선스 미확보 폴백 래더 (우아한 저하)

콘텐츠 DB의 `ref_text`/`ref_text_license` 분리(D2)가 이를 가능케 한다:

| 단계 | 상태 | 앱 동작 |
|---|---|---|
| L0 | 라이선스 확보 | verbatim 표시(오늘의말씀·근거구절 정상) |
| L1 | 미확보(출시 임박) | 근거구절은 **주소만 표시**("근거: 요 2:1-11"), 오늘의말씀은 사용자 소유 성경앱 딥링크/외부링크 유도 |
| L2 | 협상 결렬 | 오늘의말씀 기능 보류(v1.1로), 퀴즈는 주소 기반으로 정상 운영 |

> **디자인 인터페이스(갭[high]):** L1 폴백을 위해 **퀴즈 근거구절 화면에도 판권 표기 + 폴백(장·절 주소만) UI 슬롯**이 필요하다. design §11.8이 판권 슬롯을 오늘의말씀 카드에만 둔 것은 '퀴즈는 라이선스 불필요' 오판(§18.10.1)의 반영이므로, 근거구절 화면 슬롯 추가를 인터페이스 요구로 이관(§18.13).

### 18.10.3 오늘의 말씀 운영

- 진입 첫 화면 매일 1구절(QT 앵커, F7). 큐레이션 세트(365일치+절기)를 콘텐츠팀이 사전 편성, 교리 논쟁 구절 회피(§18.1.2 정신 동일).
- 발송/노출 시각은 야간 광고성 푸시 규제(갭[medium], 정통망법 21~08시)와 무관하도록 **정보성 콘텐츠**로 설계 — 새벽 노출은 앱 내 표시이지 푸시가 아님을 client/legal과 명확히 구분.

## 18.11 문제 라이프사이클 & 품질지표

### 18.11.1 문제 라이프사이클(상태 기계)

```
draft ──(자동검증 통과)──▶ reviewing ──(검수 승인)──▶ active
  ▲                              │(반려)                  │
  └──────────────────────────────┘                        │(격리 트리거)
                                                           ▼
                                    active ◀──(정상 판정/검수 복귀)── quarantined
                                       ▲                                   │
                                       └──(오타 자동수정/정답오류 수정 승인)─ fixing
                                                                           │(수정불가·중복·저작권·지속저품질)
                                                                           ▼
                                                                        retired
```

| 상태 | 정의 | 서빙 여부 |
|---|---|---|
| `draft` | LLM 초안·생성됨 | ✕ |
| `reviewing` | 자동검증 통과, 인간 검수 대기 | ✕ |
| `active` | 승인·배포, 정상 출제 | ✅ |
| `quarantined` | 신고/이상탐지로 격리, 서빙 즉시 중단 | ✕ |
| `fixing` | LLM/검수 수정 진행 중 | ✕ |
| `retired` | 폐기(수정불가 정답오류·중복·저작권 문제·지속 저품질) | ✕ (영구) |

폐기(retired) 기준: 정답오류 확정+수정 불가, 중복, 저작권 문제 구절, 재신고 반복 저품질. 폐기 시에도 감사 목적 레코드 보존(삭제 아님).

### 18.11.2 콘텐츠 품질 KPI (data 파트 대시보드)

| 지표 | 정의 | 목표 |
|---|---|---|
| 신고율 | 신고 수 / 1,000 노출 | ≤ 1.0 |
| 격리율 | 격리 문항 / 활성 문항 | ≤ 0.5%/월 |
| 오류 확정율 | answer_error 확정 / 격리 | 모니터링(품질 추세) |
| 검수 반려율 | 반려 / 초안 | 20~35%(정상 범위) |
| LLM 검증 정확도 | 자동판정 vs 최종 인간판정 일치율 | ≥ 95% |
| 자동수정 롤백율 | 롤백 / 자동수정 배포 | ≤ 2% |
| 콘텐츠 런웨이(재고 2주 버퍼) | 미노출 신규재고 / 일 신규소비 | ≥ 14일 |
| 정답률 건전성 | raw 0.98 초과·0.15 미만 문항 비율 | ≤ 3% |

## 18.13 미해소·경계 이슈 메모(다른 파트로 이관)

- **F9 신고 보상은 랭킹·티어와 분리 확정**(§18.9.9, option b): 별도 '신뢰기여' 카운터로만 집계, 주간 개인 리더보드·교회점수·명예 티어 미반영. server 아웃박스(§14.8.2)가 `report_reward`를 리더보드 롤업에서 제외하는지 구현 확인만 남음(server·monetization·data 정렬).
- **퀴즈 근거구절 화면 판권/폴백 UI 슬롯** → design(§11.8)이 현재 오늘의말씀 카드에만 둔 판권 표기 슬롯을 **퀴즈 근거구절 화면(폴백=장·절 주소만 표시)에도 추가**해야 함. F1/F9 verbatim도 라이선스 대상이므로(§18.10) '퀴즈는 라이선스 불필요' 인식 시정.
- **오늘의말씀 야간 노출 vs 푸시 규제** 경계 → legal/client가 "앱내 표시 = 정보성" 확정.
- **매크로 오탐(1.5초 연타) 이의제기**(갭[low])는 안티치트(server/qa) 소관이나, 정직한 권사의 빠른 정답이 세션포인트 무효 처리될 때 콘텐츠 품질 신뢰와 얽힘 → 소명/복구 절차를 ops와 공유.
