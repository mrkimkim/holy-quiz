# 21. 운영·CS·커뮤니티·신뢰안전

> 한 줄 목적: 중장년·교회 정서에 맞는 신뢰 가능한 운영 체계(사람이 빠르게 돕고, 명예 리더보드의 공정성을 지키며, 교단 민감 이슈에서 사고를 내지 않는 것)를 소규모 겸직 조직으로 첫날부터 굴리기 위한 실행 문서.

---

## 21.0 개요·범위·운영 원칙

### 21.0.1 제품 원칙과의 정합
이 파트의 모든 SOP는 PRD 제품 원칙에 종속된다.

| 제품 원칙 | 운영·CS·T&S에서의 번역 |
|---|---|
| 매일의 습관에 얹는다 | 새벽/저녁 사용 피크(05~07시, 20~22시)에 CS·온콜 커버리지를 맞춘다. 장애가 새벽기도 시간대에 겹치면 SEV 한 단계 상향. |
| 명예로 경쟁한다(사행성 없음) | 명예 리더보드가 유일 차별점 → 점수·초대 어뷰징을 '가장 먼저 잡아야 할 자산'으로 취급. 단, 제재는 현금 손실이 없으므로 '영구정지'보다 '점수 무효/구간 배제' 위주. |
| 교회가 팀이다 | 개인 제재보다 '교회 페이지 신뢰' 보호가 우선. 교회 단위 오해·분쟁은 개인 CS가 아니라 T&S+위기커뮤니케이션으로 다룬다. |
| 중장년이 기본값 | 채널·문구·에스컬레이션 전부 "권사님이 도움 없이 문제를 신고/문의/해결"할 수 있게 설계. 전문용어·영문·복잡한 폼 금지. |

### 21.0.2 이 문서가 다루는 것 / 다루지 않는 것
- **다룬다**: 운영 조직·겸직, CS SOP, 3개 검토 큐(오류신고/교회 이상패턴/초대 어뷰징), 교회 등록 검수, 리뷰·커뮤니티 관리, 어드민 도구 요구사항, 인시던트 런북, 운영 SLA·온콜, 공지·변경관리, 위기 커뮤니케이션.
- **다루지 않는다(타 파트 소유, 인터페이스만 정의)**: 개인정보 동의·처리방침 설계(legal), 저작권 협상(legal), 서버 권위 점수 알고리즘 구현(server), 이상탐지 모델(data), 결제·환불 정책 정의(monetization), UA·파일럿 교회 BD 실행(marketing). 본 문서는 이들의 '운영 인터페이스'와 '운영자가 지켜야 할 규칙'만 규정한다.

## 21.1 운영 조직·역할 (초기 겸직 포함)

### 21.1.1 인력 로드맵 (단계별)
현금성 보상이 없는 명예 서비스이므로 초기 운영은 '얇게, 그러나 T&S와 신학검수는 절대 0으로 두지 않는다'가 원칙.

| 단계 | 기간 | 인원(FTE) | 구성 |
|---|---|---|---|
| 파일럿 | T-2주 ~ T+4주 | 1.5 | Ops/CS 겸직 1(0.5, PM 겸직) · 신학검수 외주 1(0.5) · T&S는 PM+개발 리드가 큐 당번제 |
| 정식출시 | T+10주 | 2.5 | CS 전담 1 · Ops Lead 1(T&S 검수+교회검수+공지 겸직) · 신학검수 외주 1(0.5) · 온콜은 server/client 개발자 주간 로테이션 |
| 출시 +3개월 | ~T+22주 | 4~5 | CS 2(피크 분할) · T&S 검수 파트타임 1 · Ops Lead 1 · 신학검수 외주 확대(1.0) · 온콜 지속 |

권고: **CS와 T&S 검수는 같은 사람이 겸직하되 '시간대를 분리'**한다(오전=CS 응대, 오후=검토 큐 처리). 이유는 두 업무의 컨텍스트 스위칭 비용이 크고, CS 폭주 시 T&S가 방치되면 리더보드 공정성이 무너지기 때문. T+3개월에 분리.

### 21.1.2 역할 정의
| 역할 | 핵심 책임 | 초기 겸직 대상 |
|---|---|---|
| Ops Lead | 검토 큐 최종 판정, 교회 등록 검수 승인, 공지 발행, 인시던트 커맨더, 위기 커뮤니케이션 1차 | PM |
| CS 에이전트 | 인앱/카톡 문의 1차 응대, 매크로 운용, 결제/계정/교회등록 CS, 에스컬레이션 | Ops Lead 초기 겸직 → T+10주 전담 채용 |
| 신학검수자(외주) | 문제 신학 정합성 검수, 정답오류 판정 최종 승인, 교단 민감 이슈 자문 | content 파트 인터페이스 |
| 온콜 엔지니어 | SEV1~2 대응, 런북 실행, 리셋 관제 | server/client 개발자 주간 로테이션 |
| 데이터 당번 | 이상탐지 알림 트리아지, 봇제외 지표 검증 | data 파트 겸직 |

### 21.1.3 커버리지·근무시간 (중장년 사용 패턴 반영)
- **CS 응대 코어타임**: 평일 09~18시(비동기 티켓). 단, 접수는 24시간, 야간·주말 접수분은 다음 코어타임 시작 1시간 내 처리.
- **T&S 검토 큐 처리 창**: 평일 매일 1회(오후) + 월요일은 리셋 후 2회(주간 마감 직후 이상패턴 급증 대응).
- **온콜**: 주 7일 SEV1 페이지 대응. 새벽 피크(05~07시)·저녁 피크(20~22시)는 온콜이 '깨어있는 창'으로 지정(응답 SLA 절반).
- **월요일 00시 리셋**은 별도 관제(§21.11.1).

## 21.2 CS 채널·문의 처리 SOP

### 21.2.1 채널 전략 (결정 권고)
| 채널 | v1 채택 | 근거 |
|---|---|---|
| 인앱 1:1 문의(비동기 폼) | **채택(주채널)** | 컨텍스트(계정/교회/문제ID) 자동 첨부 가능. 단, 입력 최소화—사유 원탭 선택 + 한 줄 자유입력. |
| 카카오톡 채널 | **채택(보조·중장년 친화)** | 권사님이 가장 익숙. 단 '실시간 기대'를 유발하므로 자동응답으로 응답시간(코어타임 내)을 명시. |
| 이메일 | **채택(백업/증빙)** | 결제·개인정보 권리행사 등 기록 필요 문의. |
| 전화 상담 | **v1 미채택** | 인건비 과다. 대신 FAQ + '콜백 예약'을 v1.2 검토. |

인앱 문의 진입점은 **하단탭 '내정보' > '문의하기'** 한 곳 + **각 오류신고 후 '더 도와드릴까요?'** 링크. (ux/client 의존: §21.12)

### 21.2.2 문의 유형·분류·SLA
접수 시 **원탭 유형 선택**(중장년 자유서술 부담 완화):

| 유형 | 예시 | 1차응답 SLA | 해결목표 | 처리 주체 |
|---|---|---|---|---|
| 결제/구독 | 결제했는데 광고가 안 없어져요 | 12h | 48h | CS→(영수증검증 server) |
| 계정/로그인 | 폰 바꿨더니 점수가 사라졌어요 | 12h | 48h | CS→계정복구 SOP |
| 교회 등록/변경 | 우리 교회가 검색이 안 돼요 | 24h | 영업일 48h | CS→교회검수 |
| 문제 오류 | 정답이 틀린 것 같아요 | (자동) | 큐 SLA(§21.3) | 오류신고 큐 |
| 어뷰징 소명(이의제기) | 갑자기 점수가 0이 됐어요 | 24h | 72h | CS→T&S |
| 버그/오작동 | 앱이 자꾸 꺼져요 | 24h | 릴리스 연동 | CS→온콜 |
| 신고(부정/욕설 등) | 특정 교회가 조작하는 것 같아요 | 24h | 72h | CS→T&S |
| 기타/제안 | 기능 건의 | 48h | best-effort | CS |

전 유형 공통: **접수 즉시 자동 확인 메시지**("접수되었습니다. ○○시간 내 답변드릴게요") 발송. 중장년은 '접수됐는지'를 가장 불안해하므로 필수.

### 21.2.3 티켓 라이프사이클
`접수(자동확인) → 분류 → 처리(매크로/에스컬레이션) → 답변 → 확인대기(3일) → 자동종결`
- 재오픈은 답변 후 7일 내 사용자 회신 시 자동. 
- 종결 시 만족도 1탭('도움됐어요/아니에요')만 수집(별점·서술 강요 금지).

### 21.2.4 응대 톤 가이드 (중장년·교회 정서)
- 호칭: 기본 "○○님". 교회 직분 노출 금지(개인정보·오호칭 리스크). 
- 문장: 짧고 큰 단위로. 한자어·영문·전문용어 금지("환불" O, "리펀드" X / "포인트 무효" 대신 "이번 주 점수가 반영되지 않았어요").
- 사과·공감 먼저, 원인·조치는 그 다음. 
- 신앙 표현은 **중립·존중**. "은혜로운 하루 되세요" 같은 관용 인사는 OK, 특정 교리·교단 언급은 금지.
- 절대 하지 말 것: 사용자를 '어뷰저'로 단정, 규정 원문 그대로 붙여넣기, "약관 제○조 참고" 식 응대.

### 21.2.5 매크로/응답 템플릿 (핵심 5종, 그대로 사용 가능)
1. **결제했는데 광고 유지**  
"○○님, 결제 확인이 조금 늦어질 수 있어요. 앱을 완전히 껐다 켜주시겠어요? 그래도 광고가 보이면, 결제하신 폰의 앱스토어(구글/애플) 그대로 확인해 드릴게요. 결제 취소 걱정은 안 하셔도 됩니다."  
→ 내부: 서버 영수증검증(server) 조회 → 미반영이면 수동 권한부여 + 원인 티켓.

2. **폰 변경 후 점수 소실**  
"놀라셨죠, ○○님. 점수는 사라지지 않습니다. 예전에 로그인하실 때 쓰신 **카카오 계정 그대로** 다시 로그인해 주세요. 카카오 계정이 바뀌셨다면, 예전 닉네임과 교회 이름을 알려주시면 저희가 찾아 연결해 드릴게요."  
→ 내부: 계정복구 SOP(§21.4.7 / server 의존).

3. **교회 검색 안 됨**  
"○○님 교회를 저희가 함께 찾아드릴게요. 교회 이름과 **지역(시/구)**만 알려주시겠어요? 목록에 없으면 저희가 직접 등록해 드립니다(하루 이틀 정도 걸릴 수 있어요)."  
→ 내부: 교회 등록 검수 큐로 전환.

4. **어뷰징 오탐 소명(정직한 빠른 응답자)**  
"○○님, 확인해 보겠습니다. 실력이 좋으셔서 빠르게 푸신 것으로 보이는데, 시스템이 지나치게 빠른 연속 입력을 자동 방어하는 과정에서 일부가 반영되지 않았을 수 있어요. **점수는 복구 가능**하며, 이번 건 다시 살펴보고 조치하겠습니다."  
→ 내부: T&S가 세션 로그 확인 → 오탐이면 점수 소급 복구 + 임계값 튜닝 티켓(qa 의존, §21.12).

5. **교회 대항이 분열적이라는 항의** → §21.5.3 스크립트 사용(위기 라벨).

### 21.2.6 에스컬레이션 경로
`CS 에이전트 → Ops Lead(판정/보상/제재) → 신학검수(교리)·Legal(법)·온콜(장애)`. 
자동 에스컬레이션 트리거: 결제 이중청구, 개인정보 삭제·열람 요청, 미성년 추정 사용자, 교단·언론 언급, 동일 이슈 3건+ 동시 유입.

## 21.3 신뢰·안전 운영 (3개 검토 큐)

> 명예 리더보드가 유일 차별점이므로 T&S는 '있으면 좋은 것'이 아니라 '없으면 제품이 붕괴하는 것'이다. 3개 큐 모두 **자동 신호 → 격리/보류 → 사람 판정 → 처분 → 감사로그**의 동일 골격을 쓴다.

### 21.3.1 F9 오류신고 검수 큐

#### 자동격리 트리거 (PRD 준수)
| 트리거 | 임계값 | 격리 즉시성 |
|---|---|---|
| 신고 누적 | 3건(동일 문제, 24h 무관) | 즉시 |
| 정답률 이상치 | 노출 50회+ & **원(raw) 정답률 15% 미만** | 즉시 |
| 특정 오답 쏠림 | 오답 중 한 선택지 60%+ 집중 | 즉시(정답 오설정 의심) |

격리=해당 문제 즉시 출제 중단. 진행 중 세션에는 영향 없음(다음 서빙부터 제외). server 의존.
- **정답률 지표 단일 규격**: 격리 트리거는 **원(raw) 정답률**을 사용한다(server §14.11.1과 동일 산출 필드). 격리는 되돌리기 쉬운 안전 게이트이므로 응시자 실력 보정 없는 단순 raw로 통일한다. 콘텐츠(18.9.2)의 '정규화 정답률 15% 미만'은 본 규격(raw)으로 정렬 필요. server 집계가 `raw correct_rate`를 산출하도록 정렬(§21.12).

#### LLM 자동검증 → 처리 분기
LLM 검증기 입력=격리문제+근거구절 원문+신고사유. 출력=판정(정상/오타/정답오류/유보)+신뢰도+수정안.

| LLM 판정 | 신뢰도 | 처리 | SLA |
|---|---|---|---|
| 정상 | ≥0.90 | 자동 복귀 + 신고자에 "확인결과 정상" 안내, 로그 | 자동판정 24h |
| 오타(경미) | ≥0.95 **AND** 가드레일 통과 | 자동수정 후 즉시 복귀 | 자동 |
| 오타 | 0.90 미만 또는 가드레일 실패 | 인간검수 | 검수 72h |
| 정답오류 | 무관 | 수정안 생성 → **신학검수 승인 대기(무인배포 금지)** | 검수·승인 72h |
| 유보/저신뢰 | <0.90 | 인간검수 | 검수 72h |

> 주: 신뢰도 **≥0.90은 '무수정 자동복귀'(본문 변경 없음)에만** 적용된다. **본문을 바꾸는 자동수정은 ≥0.95 AND 2모델 합의 AND 가드레일** 충족이 필수이며, 이 임계가 자동수정의 유일 기준이다. content 18.9.5 표의 '자동수정 ≥0.90'은 본 규격(≥0.95)으로 정렬.

#### 오타 자동수정 무인배포 가드레일 (단일 규격 — content·server·qa 공유)
이 화이트리스트가 **오타 무인 자동수정의 유일 규격**이며, 파트 간 수치가 충돌하면 **본 규격이 우선**한다(오류신고 큐 자동수정 배포의 A=Ops Lead). '정답 불변'만으로는 본문 훼손을 못 막으므로 **AND 조건 전부 충족 시에만** 자동배포:
- [ ] 수정 대상이 **문제 지문(question)에 한정**. **해설·정답 선택지·오답 선택지·근거구절 텍스트는 자동수정 절대 금지**. → '해설 자동수정 허용 여부' 결정: **불허**(해설은 길고 신학·문맥 훼손 리스크가 커 무인배포 대상에서 제외).
- [ ] LLM 신뢰도 ≥ 0.95 **AND 2모델 합의**(독립 2개 검증기가 동일 판정·동일 수정안일 때만 통과).
- [ ] before/after **편집거리 ≤ 2** (자모·띄어쓰기·문장부호 수준).
- [ ] 수정 후 정답 인덱스·선택지 집합·근거구절·**해설 완전 동일**(diff 가드).
- [ ] 최근 30일 내 동일 문제 자동수정 이력 없음(반복 자동수정 차단).
- **롤백**: 자동수정 후 **48h 관찰창**. 신규 신고 1건이라도 유입 시 자동 재격리+인간검수. 
- **감사로그 필수 필드**: 문제ID, before/after 전문, LLM 판정·신뢰도·2모델 합의여부, 편집거리, 적용시각, 롤백여부, 관찰창 신고수. (server 의존)
- 자동수정은 **일 상한 20건**, 초과분은 전량 인간검수 큐로(폭주 시 무인배포 오판 확산 차단).
- **파트 정렬 필요**: content(18.9.6)의 허용 필드 {question, **explanation**}·편집거리 ≤5자&원문 10%·신뢰도 ≥0.90(18.9.5)은 본 규격(**지문만·≤2·≥0.95·2모델 합의**)으로 수정하고 explanation을 화이트리스트에서 제거한다. server(14.11.2)·qa(20.6.4)는 동일 규격을 임계로 명시. LLM 검증기 규칙은 **배포 게이트 전 프리즈**(v1.1 개선도 이 프리즈본 대비 회귀검증)하고 qa 금지 골든셋(20.6.4)에 반영한다. (§21.12)

#### 신고자 보상 처리 (PRD F9)
- 채택 시: 푸시 + 소량 포인트, 마일스톤 배지(파수꾼 3 / 성경지킴이 10). 
- 운영 규칙: **동일 문제 다수 신고 시 최초 유효 신고자 1인만** 채택 보상(중복 파밍 방지). 기각 시 감점·불이익 없음(신고 위축 방지). 월간 리포트에 채택률·평균 처리시간 공개.

### 21.3.2 교회 이상패턴 검토 큐

#### 이상 신호(자동, data 의존) → 처분 등급
| 신호 | 정의(예시 임계) | 1차 처분 |
|---|---|---|
| 계정 군집 담합 | 동일 교회 상위20 중 3+ 계정이 동일 기기지문/IP대역/생성시각 클러스터 | 관찰 라벨 → 확증 시 해당 계정 주간점수 무효 |
| 시계 조작 | 서버시간 대비 클라이언트 출석·연속 타임스탬프 불일치 | 해당 출석/연속 무효(서버시간 기준으로 재계산) |
| 교회 홉핑 | 월1회 변경 규칙 우회 시도 반복, 마감 직전 교회 이동 | 변경 거부 + 쿨다운, 기여 소급 불가 |
| 상위20 조작 | 단일 계정 비정상 급증(정상 상한의 5σ+) + 파밍패턴 동반 | 세션점수 무효 + 개인 큐 이관 |

#### 처분 사다리 (교회는 '팀'이므로 개인 위주 제재)
`관찰(라벨만) → 경고(당사자 안내) → 주간점수 무효(해당 계정) → 리더보드 구간 배제(재범) → 교회 페이지 '검토중' 표시(다수 확증 시, 위기커뮤니케이션 연동)`
- 원칙: **교회 전체를 벌하지 않는다.** 조작은 개인 계정 단위로 무효화하고, 교회 순위는 정상 기여분으로 재계산. 교회 통째 강등은 위기 이슈이므로 Ops Lead 단독 판정 금지(신학검수·legal C).
- 서버시간 기준 출석·기여 소급 정책은 server 의존(§21.12).

### 21.3.3 초대 어뷰징 검토 큐

#### 유효초대 규칙(PRD) 준수
유효초대 = 신규가입 **AND** 교회등록 **AND** 퀴즈 20문제 완료(3조건 전부). 동일기기 차단, 일일 인정 상한 5.

#### 추가 이상 신호 → 처분
| 신호 | 정의 | 처분 |
|---|---|---|
| 기기팜 | 동일 기기지문에서 다수 신규 계정 발생 | 유효초대 불인정 + 계정 군집 큐 연동 |
| 자기초대 링(순환) | A→B→A 또는 폐쇄 소집단 상호초대 | 그래프 순환 탐지 → 초대왕 랭킹 제외 |
| 마감 직전 대량 초대 | 주간·월간 리셋 직전 급증 | 지연 정산 후 사후 무효 가능 |
- 보상은 **명예 전용(배지, 포인트 없음)·퀴즈 랭킹과 분리**(PRD) → 어뷰징 유인이 낮으므로 처분은 '초대왕 랭킹 배제' 위주, 계정정지는 기기팜 확증 시에만.

### 21.3.4 공통 에스컬레이션·처분 매트릭스
| 확신도 | 영향범위 | 판정자 | SLA |
|---|---|---|---|
| 자동 신호(미확증) | 개인 | 자동 라벨 | 즉시 |
| 사람 확증(단순) | 개인 | T&S 검수(Ops Lead) | 72h |
| 사람 확증(복합) | 교회/다수 | Ops Lead + Legal/신학 C | 5영업일 |
| 언론·교단 연루 | 대외 | 위기커뮤니케이션(§21.10) | 즉시 |
- 모든 처분은 **이의제기 창구**(CS 유형 '어뷰징 소명') 필수. 오탐 복구 SLA 72h. 정직한 사용자 오탐(예: 빠른 권사님)은 소명 시 즉시 복구 + 임계값 튜닝 티켓.

## 21.4 교회 등록 검수 운영

### 21.4.1 verified 시딩 운영
- **역할 한계 명시**: 시딩 데이터 소스·수집 합법성·비용은 **data/legal 파트 소유**(장소검색 API 약관 위반 리스크는 §21.12 의존). 본 파트는 **검증·정제·중복제거·상태관리 운영**을 담당.
- 운영 절차: 시딩 후보(대형교회 500~1,000) → (1) 교회명·주소·교단 정규화 → (2) 동명이교회 지역표기 부여 → (3) 공개 확인 가능한 최소정보만 표기(전화·담임목사 실명 미노출) → (4) `verified` 플래그 + 시딩 출처 로그.
- **verified 배지 정책**: '검증됨'은 '실재 교회 레코드'를 뜻하지 '교회 지도부 공인'을 뜻하지 않는다(오해 방지 툴팁). 지도부 공인은 클레임(§21.4.6)으로 승격.

### 21.4.2 개척교회 직접등록 승인 SOP
| 단계 | 처리 | SLA |
|---|---|---|
| 1. 접수 | 사용자가 교회명+지역+(선택)교단 입력 → 검수큐 | 즉시 |
| 2. 중복 체크 | 반경/명칭 유사도로 기존 레코드 매칭 제시 → 있으면 '기존 선택' 유도 | 자동 |
| 3. 실재 확인 | 지도·검색으로 최소 실재성 확인(주소 존재/명칭 일치) | 영업일 48h |
| 4. 승인/보류/반려 | 승인=활성화 / 보류=추가정보 요청 / 반려=허위·중복·비교회 | 48h |
- 승인 임계: '실재 개연성 + 중복 아님'이면 승인(문턱 낮게, 개척교회 배제 방지). 애매하면 보류로 사용자에게 확인.
- **자동승인 금지**: 직접등록은 100% 사람 승인(허위 교회 정체성 등록 리스크). 단 성수기 폭주 시 '조건부 즉시활성 + 사후검수 24h' 옵션(반려 시 소급 비활성).

### 21.4.3 중복 교회 처리
- 동명교회: 지역표기(시/구/동)로 구분 강제. 사용자에게 후보 리스트 제시(PRD F4).
- 사후 중복 발견: **대표 레코드로 병합**, 성도·기여포인트·주간점수 합산 이관, 잔여 레코드는 tombstone(리다이렉트). 병합 규칙 상세는 §21.4.5.

### 21.4.4 허위·부적절 교회 처리
- 반려 사유: 실재 불명, 장난·비속어 명칭, 교회 아닌 단체, 정치·상업 목적. 
- 이미 활성화된 허위 레코드: 즉시 비활성 + 소속 사용자에게 '교회 재선택' 안내 푸시(개인 점수는 보존, 교회 귀속만 해제). 악의적 반복 등록자는 초대/등록 제한.

### 21.4.5 교회 병합·분립·폐업·이전·개명 규칙 (엣지케이스)
| 사건 | 판정·처리 | 기여/이력 |
|---|---|---|
| 개명 | 동일 레코드 명칭 변경(별칭 보존) | 이력·기여 유지 |
| 이전(주소변경) | 동일 레코드 주소 변경 | 유지. 규모리그 재산정은 다음 주부터 |
| 병합 | 대표 레코드로 합산 이관 | 주간점수·누적기여 합산, 상위20 재계산 |
| 분립 | 신규 레코드 생성, 사용자는 개별 재선택 | 과거 교회 이력은 원 레코드에 잔류(소급 분할 안 함) |
| 폐업 | 레코드 `closed`, 리더보드 비노출 | 이력 보존, 재개시 복원 |
- 판정 주체: Ops Lead. 병합/분립은 **되돌리기 어려우므로 감사로그 + 2차 확인**(체크리스트 승인). server 의존.

### 21.4.6 교회 소유권·목회자 클레임 최소 창구 (v1 경량)
- 대시보드(B2B)는 v2지만, **최소한의 정정·클레임 창구**는 v1 운영 필요(비인가 대표등록 리스크).
- 절차: 지도부가 CS로 '우리 교회 정보 정정/대표 등록' 요청 → CS가 최소 확인(주보·교회 홈페이지·직인 등 공개 확인 가능한 근거 1종) → Ops Lead 승인 → 교회 레코드에 `claimed` 플래그 + 정정.
- v1 권한은 '정보 정정'까지만(순위 조작 방지 위해 점수·성도 관리 권한 부여 금지).

### 21.4.7 교회변경 월1회 운영 & 계정 이전
- 교회변경 월1회(PRD). 변경 시 **기존 주간 기여는 이전 교회에 잔류**(소급 이동 금지, 홉핑 어뷰징 차단). 
- 계정 이전/기기변경/카카오 계정변경 복구: CS가 '예전 닉네임+교회+대략 가입시기'로 후보 조회 → 본인확인(마지막 결제내역/연속출석일 등 소유자만 아는 정보 1종) → server 계정 병합. 포인트·티어·연속출석 승계. (server 의존, §21.12)

## 21.5 커뮤니티·리뷰 관리

### 21.5.1 스토어 리뷰 대응 SOP
- 모니터링: 앱스토어·플레이스토어 신규 리뷰 **매일 1회 확인**, 평점 3점 이하·키워드('버그','환불','틀림','조작','분열') 알림.
- 응답 정책: **모든 3점 이하 + 오류지적 리뷰에 24~48h 내 공개 답글**. 톤=§21.2.4. 개인정보·이슈ID 노출 금지, "앱 내 문의로 도와드리겠다"로 채널 전환.
- 답글 템플릿(1점 버그): "불편을 드려 정말 죄송합니다. 말씀하신 문제를 바로 확인하겠습니다. 번거로우시겠지만 앱 '내정보 > 문의하기'로 기기 종류를 알려주시면 빠르게 조치해 드리겠습니다."

### 21.5.2 리뷰테러 방어 플레이북
교단 갈등·경쟁 반감 등으로 단기간 저평점 폭탄이 올 수 있음.
| 단계 | 신호 | 대응 |
|---|---|---|
| 탐지 | 24h 내 1점 리뷰 급증(평소 대비 5배+) + 유사문구 반복 | 위기 라벨, 캡처 보존 |
| 분류 | (a)정당한 장애 폭주 (b)조직적 테러 (c)교단 이슈 | Ops Lead 판정 |
| 대응 | (a)→장애 공지+개별응답 (b)→스토어 정책위반 신고(중복/무관/스팸) + 정중한 표준 답글 (c)→§21.5.3 | 채널별 |
| 회복 | 만족 사용자에게 리뷰 요청 인앱 프롬프트(맥락기반, 승급/주간결산 직후) | data 의존 |
- 원칙: 테러 리뷰와 **논쟁하지 않는다**. 동일 정중 템플릿 + 사실 정정만. 삭제 유도·허위 반박 금지.

### 21.5.3 교단 민감 이슈 대응 스크립트 (시나리오별, 그대로 사용)
신학은 신뢰의 핵심 리스크(PRD 최상위). CS가 즉답하지 말고 **표준 스크립트 + 필요 시 신학검수 에스컬레이션**.

- **A. "교회 대항이 세속적·분열적이다"**  
"소중한 말씀 감사합니다. 저희는 경쟁 자체보다 **함께 성경을 더 가까이 하는 습관**을 돕고자 만들었습니다. 순위는 서로를 응원하는 장치로 두었고, 어떤 현금성 보상도 없습니다(순수 명예). 불편하시면 교회 표시 없이 개인으로만 이용하실 수도 있습니다. 더 좋게 만들 의견 있으시면 언제든 들려주세요."

- **B. "우리 교단 교리와 다른 문제가 있다"(예: 세례/침례, 종말론)**  
"확인해 주셔서 감사합니다. 저희는 **해석·교리가 갈리는 주제는 출제하지 않는 것을 원칙**으로 하며, 사실(사건·인물·지명) 중심으로만 냅니다. 혹시 그렇지 못한 문제가 있었다면 저희 실수입니다. 문제 화면의 '신고'로 알려주시면 신학 검수를 거쳐 바로잡겠습니다."  
→ 내부: 오류신고 큐 + 신학검수 에스컬레이션, 교리 논쟁 문제는 출제 풀에서 제외 검토.

- **C. "특정 번역본·표기가 우리와 다르다"**  
"표기는 개역개정을 기준으로 통일하고 있습니다. 다른 번역본을 쓰시는 분들께 낯설 수 있는 점 양해 부탁드립니다. 근거 구절은 함께 표시해 직접 확인하실 수 있게 했습니다." (저작권·번역본 이슈는 legal 의존)

- **D. "왜 가톨릭/특정 교단은 없나"**  
"현재는 개신교를 중심으로 시작했고, 앞으로 더 넓히려 준비 중입니다. 기다려 주셔서 감사합니다." (확장 여부는 오픈퀘스천, 확정 약속 금지)

원칙: **교리 옳고 그름을 CS가 판정하지 않는다.** '사실 기반·해석 미출제' 원칙을 반복하고, 문제 자체 오류는 검수로 넘긴다.

### 21.7.2 런북 (유형별 핵심)
- **장애(리셋 실패/썬더링허드)**: 지표 확인 → 읽기전용 폴백 여부 판단 → 리더보드 순위표시 일시 캐시고정 → 사용자 공지 배너("잠시 순위 집계 중입니다") → 원인 조치 → 정합성 재검증(§21.11.1과 연계). server 의존.
- **데이터(정합성 손상: 점수/기여 오계산)**: 쓰기 동결 → 스냅샷 확보 → 영향범위 산정 → 롤백 or 보정 배치 → 사용자 사과·보정 공지. 절대 조용히 수정 금지(명예 서비스, 신뢰 직결).
- **보안(무단접근/치트 대량/개인정보 유출)**: 접근 차단·자격증명 회수 → 영향범위·신고의무 판단(legal 즉시 소집) → 증거 보존 → §21.10 위기 커뮤니케이션. 개인정보 유출 의심은 **자동 SEV1 + Legal I**.
- **결제 이중청구**: 대상 식별 → 자동 환불/조정 → 개별 사과 → 재발 원인.

### 21.7.3 온콜·지휘·포스트모템
- 온콜: 개발자 주간 로테이션, SEV1 페이지 응답 15분. 백업 온콜 1인 지정.
- 지휘: 커맨더 1인(의사결정), 커뮤니케이터 1인(공지·CS 조율), 나머지 실행. 
- 포스트모템: SEV1/2는 72h 내 무비난(blameless) 회고 + 액션아이템 오너·기한. 공개 여부는 위기 등급에 따라 결정.

5. **사후**: 조치 결과 투명 공지 + 재발방지. 은폐·조용한 수정 절대 금지(명예 서비스, 신뢰가 자산).

### 21.10.3 사전 준비 성명 템플릿 (골든타임 즉시 발행용)
- **신학오류**: "말씀퀴즈를 아껴 주시는 여러분께. 최근 지적해 주신 ○○ 문제를 확인하고 있습니다. 저희는 해석이 갈리는 주제는 출제하지 않는 것을 원칙으로 하며, 확인되는 오류는 신학 검수를 거쳐 신속히 바로잡겠습니다. ○○일까지 조치 결과를 알려드리겠습니다. 알려 주셔서 감사합니다."
- **조작 논란**: "리더보드는 여러분의 신뢰로 유지됩니다. 제기된 사안을 진지하게 조사 중이며, 확인되는 부정 기여는 개인 단위로 무효화합니다. 조사 원칙과 결과를 투명하게 공유하겠습니다."
- **개인정보**: (legal·홍보 공동 작성, 사전 승인본 보관. 법정 신고·통지 의무 우선.)

## 21.12 의존성·인터페이스 / 오픈 이슈 (요약)
상세 의존은 dependencies 필드 참조. 핵심:
- **server**: 어드민 도구, 서버 권위 점수/재격리, 교회 병합·서버시간 출석, 계정 병합(복구), 영수증검증, 리셋 관제 폴백, 감사로그. **격리 트리거용 `raw correct_rate` 산출**(§21.3.1 단일 규격), 오타 자동수정 가드레일 집계·diff가드(정답/선택지/근거/해설 불변) 및 2모델 합의·롤백 관찰창 로깅.
- **legal**: 민감정보(종교) 동의·처리방침, 미성년·복구 본인확인, 저작권(근거구절), 야간·광고성 푸시 동의, 개인정보 열람·삭제 권리행사 처리 절차.
- **content/신학검수**: 정답오류 최종 승인, 교단 민감 문제 제외, 콘텐츠 소진 대비 증분 수급. **오타 자동수정 화이트리스트를 §21.3.1 단일 규격으로 정렬**(허용 필드=지문만, explanation 제거, 편집거리 ≤2, 신뢰도 ≥0.95, 2모델 합의) 및 **격리 트리거 정답률 지표를 raw로 정렬**(18.9.2 정규화 → raw).
- **data**: 이상탐지 신호(계정 군집·시계조작·기기팜), 봇제외 지표 정의, 실험 플래그(파일럿 상위N·명칭). 난이도 재라벨 지표(raw vs 정규화) 통일은 content·data 소관(본 문서 범위 밖) — §21.3.1 격리 규격과 지표 일관성 확인 요청.
- **qa**: 안티치트 오탐 임계값 튜닝 루프. **오타 자동수정 단일 규격을 금지 골든셋(20.6.4)에 반영**하고 LLM 검증기 프리즈본 대비 회귀검증(배포 게이트 전 프리즈).
- **monetization**: 결제·환불·자동갱신 고지 정책(CS가 집행), 영수증검증 연동.
- **marketing**: 리뷰 요청 프롬프트, 리뷰테러 시 UA 조율, 파일럿 교회 BD.
- **ux/client/branding**: 문의·신고 진입점, 공지 배너·팝업 컴포넌트, 공지 톤·명칭.
