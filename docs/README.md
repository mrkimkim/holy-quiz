## 작성 방법론

- **다중 에이전트 병렬 작성:** 파트별 전문가 관점의 문서를 독립적으로 작성한 뒤, 서로를 교차 검증했습니다.
- **3개 렌즈 상호 검증:** ① 정합성(문서 간 모순·수치 충돌) ② 커버리지(PRD F1~F9·리스크·오픈퀘스천의 담당자 존재) ③ 의존성(파트 간 인터페이스·실행 순서). 총 **42건 발견(High 5 · Medium 26 · Low 11)**, 이를 반영해 **13개 파트 문서 전부 개정**했습니다.
- **원칙:** PRD의 4대 제품 원칙(매일의 습관 / 명예로 경쟁 / 교회가 팀 / 중장년이 기본값)과의 정합을 모든 문서의 검증 기준으로 삼았습니다.

## 착수 전 반드시 결정해야 할 핵심 이슈 (상호 검증이 발견한 High 항목)

로드맵의 **M0(사전 준비)** 에서 해소해야 하는 크리티컬 결정들입니다. 상세는 [`30-cross-verification.md`](./30-cross-verification.md)와 [`01-planning-gaps.md`](./01-planning-gaps.md) 참조.

1. **단일 재무 기준선 확정** — 수익화·데이터·조직 문서가 광고 ARPDAU(₩15~₩20.5)·DAU/MAU(25% vs 28%)를 서로 다르게 써서 "월 2,000만원 달성" 결론이 엇갈림. PRD KPI(25%) 기준으로는 세 모델 모두 목표 미달 → **목표 MAU 상향 또는 KPI 재정의를 경영 결정으로 확정**해야 함.
2. **성경 본문(근거구절) 라이선스** — PRD의 "퀴즈는 라이선스 불필요"는 F1 근거구절·F9 원문의 **축자 표시**에는 오판. 대한성서공회 라이선스 협상을 **출시 전 필수 트랙(블로커)** 으로, 실패 시 폴백은 "장·절만 표기". 오늘의말씀 번역본은 개역개정으로 통일.
3. **개인정보(민감정보) 설계** — 종교·교회소속은 PIPA §23 민감정보. 별도 동의·강화보호·B2B 목적외 이용 동의·만 14세 미만 연령 게이트가 **전무** → 출시 전 구축 필수.
4. **서버 권위(anti-cheat)** — 교회 대항전은 "우리 교회를 위해" 점수를 조작할 강한 유인을 만듦. 점수·콤보·티어의 **서버 권위 계산 + 요청 서명 + 재전송 방지**가 없으면 유일한 차별점(명예 리더보드)이 붕괴.
5. **보상형 광고 공정성 가드레일** — "다음 20문제 2배 포인트"의 배율분을 **교회 대항 주간 합산에서 제외**하도록 서버 데이터모델 확정(개인 티어에는 반영). 확정 전 v1.1 보상형 광고 착수 금지.
6. **오프라인 채점 모델 / MMP·딥링크 SDK 단일 확정** — 클라이언트·서버의 오프라인 정책 충돌, F8 자동귀속용 MMP(AppsFlyer vs Airbridge vs Adjust) 3파트 상충을 착수 전 통일.
7. **콘텐츠 수급·검수 병목** — 신학 검수 1인 SPOF + "월 증분 500 << 헤비유저 소비"의 미스매치. 검수 백업·자문위, 증분 파이프라인 강화 필요.
