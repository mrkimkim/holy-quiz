# 말씀퀴즈 — 기능 명세서 (Functional Specification)

**앱이 제공하는 모든 기능과 상세 동작, 그리고 가능한 사용자 시나리오를 정의한다.**

---

## 0. 문서 범위 · 원칙 · 용어

### 0.1 다루는 것 / 다루지 않는 것

- ✅ **다룬다:** 앱이 제공하는 기능 전체, 각 기능의 상세 동작 규칙, 상태와 전이, 시스템의 반응, 그리고 **가능한 모든 사용자 시나리오**(정상·경계·오류·악용).
- ❌ **다루지 않는다:** 화면 구성·레이아웃·컴포넌트 배치·비주얼·내비게이션 구조 등 **UI 표현**. (별도의 UX/디자인 문서에서 다룸.) 이 문서는 "무엇을 할 수 있고, 시스템이 어떻게 반응하며, 각 상황에서 사용자가 무엇을 경험하는가"만 기술한다.

### 0.2 표기 규칙

- `[튜닝]` — 구체 수치·임계값은 밸런싱/상세 설계에서 확정. 이 문서는 **규칙의 존재와 동작 방식**만 정의한다.
- **시나리오 표기:** `정상`(happy path) · `경계`(edge) · `오류`(error/실패) · `악용`(abuse/방어).

### 0.3 용어

| 용어 | 정의 |
|---|---|
| 성도 | 특정 교회에 소속(등록)한 사용자 |
| 우리 교회 | 사용자가 소속으로 지정한 교회 |
| 명예 / 등급 | 실력·기여로 쌓이며 하락하지 않는 성취 상징(현금·재화 아님) |
| 근거 구절 | 각 문제가 필수로 갖는 성경 출처(예: 창세기 12:1) |
| 유효 초대 | 어뷰징 방어 조건을 모두 충족해 성장 실적으로 인정되는 초대 |
| 격리 | 오류 의심 문제를 출제 풀에서 임시 제외한 상태 |
| 세션 | 사용자가 퀴즈를 시작해 종료할 때까지의 한 번의 풀이 흐름 |

## 2. 기능 상세

---

### A. 계정·인증

**A.0 개요.** 중장년 사용자가 가장 익숙한 방식으로 최소 마찰로 진입하고, 이후 재실행 시 다시 로그인하지 않도록 세션을 유지한다.

**A.1 기능**
- 간편 로그인(카카오 우선, iOS 심사 요건에 따라 Apple 로그인 병행)
- 세션 유지(자동 로그인)
- 로그아웃
- 계정 삭제(탈퇴)

**A.2 상세 동작**
- 최초 로그인 시 계정이 생성되고, 이후 동일 수단으로 로그인하면 동일 계정에 연결된다.
- 로그인 성공 후에는 재실행 시 자동으로 인증 상태가 복원된다.
- 하나의 사용자 = 하나의 계정 = 하나의 명예/기여 이력. 로그인 수단이 여러 개여도 동일 사용자로 귀속된다(계정 병합 정책은 [상세 설계]).
- 계정 삭제 시: 개인 식별 정보와 개인 활동 이력은 파기 대상이 되며, 삭제가 미치는 범위(누적 명예·교회 기여·초대 귀속의 처리)는 [상세 설계]에서 규칙으로 확정한다. 삭제는 되돌릴 수 없음을 사용자에게 사전 고지한다.

**A.3 상태**
`비로그인` → (로그인) → `로그인/세션 유효` → (세션 만료·로그아웃) → `비로그인` / (탈퇴) → `삭제됨`

**A.4 사용자 시나리오**
- `정상` 첫 사용자가 카카오로 로그인 → 계정 생성 → 온보딩(B)로 진입.
- `정상` 재실행 → 자동 로그인 → 직전 상태로 복귀.
- `경계` 기기를 바꿔 같은 수단으로 로그인 → 동일 계정·이력 그대로 복원.
- `경계` 앱 삭제 후 재설치 → 같은 수단 로그인 시 이력 유지(서버 보관분 기준).
- `오류` 로그인 중 네트워크 실패 → 실패를 알리고 재시도를 허용, 부분 계정이 생성되지 않는다.
- `오류` 인증 수단 제공자 장애 → 사용자에게 원인을 알리고 대체 수단(가능 시)을 안내.
- `악용` 동일인이 다수 계정을 만들어 초대·순위를 조작 시도 → G/E의 방어 규칙과 연동해 무효화(§G.4, §E.4).

### B. 온보딩

**B.0 개요.** 40~70대가 도움 없이 첫 경험을 즐겁게 통과하도록, 최소 단계로 "재미 → 소속"까지 데려간다.

**B.1 기능**
- 접근성 초기 설정(글씨 크기 선택)
- 난이도 진단(초기 몇 문항, 이 구간은 광고 없음)
- 첫 성취(첫 등급/명예) 부여 연출
- 교회 등록 유도(건너뛰기 가능)

**B.2 상세 동작**
- 온보딩 첫머리에서 글씨 크기를 고를 수 있고, 선택은 즉시 전역에 반영된다(K와 연동).
- 진단 문항의 결과로 **초기 난이도가 자동 배정**된다. 진단 구간에는 광고가 노출되지 않아 첫인상을 해치지 않는다.
- 진단을 마치면 **첫 성취를 부여**받아, 시작부터 "쌓이는 명예"의 감각을 전달한다.
- 마지막에 교회 등록을 유도하되 **건너뛸 수 있다.** 건너뛰어도 앱 사용에는 지장이 없으며, 이후 상시 재유도한다(F와 연동).

**B.3 상태**
`온보딩 미완료` → (진단 완료) → `기본 사용 가능` → (교회 등록) → `성도`
- 교회 미등록 상태에서도 퀴즈·명예·개인 리더보드 등 대부분 기능을 사용할 수 있고, 교회 대항 관련 기능만 제한된다.

**B.4 사용자 시나리오**
- `정상` 큰 글씨 선택 → 진단 → 첫 성취 → 교회 등록까지 완주 → 성도로 시작.
- `정상` 교회 등록만 건너뜀 → 이후 홈 진입 시 등록을 다시 권유받음.
- `경계` 진단 도중 앱 종료 → 재실행 시 진단 지점부터 이어서 진행(진단 미완료는 미완료로 유지).
- `경계` 진단에서 모두 정답/모두 오답 → 그 결과에 맞는 초기 난이도가 배정되되 이후 실력에 따라 재보정된다(C.2).
- `오류` 진단 문항 로딩 실패 → 재시도 안내, 진단을 완료해야 다음 단계로 진행.

### C. 퀴즈 플레이 (코어 루프)

**C.0 개요.** 세션·횟수 제한 없이 **무제한**으로 즐기는 4지선다 성경 퀴즈. 언제든 시작하고 언제든 끝낸다. 이 앱 경험의 심장.

**C.1 기능**
- 무제한 풀이(세션·하트 제한 없음)
- 4지선다 단일 형식, 1문제씩 진행, 즉시 채점
- 정답 시 **근거 구절** 표기, 오답 시 **해설** 제공
- 카테고리 선택(구약 / 신약 / 인물 / 사건·지명 / 통합 랜덤)
- 난이도(쉬움·보통·어려움), 실력 기반 자동 조정
- 콤보(연속 정답 보너스)
- 오답노트 자동 저장
- 재출제 로테이션(이미 푼 문제 관리)
- 부정 방어(반복 채굴·자동 입력 방지)를 사용자 흐름에 녹여 처리

**C.2 상세 동작**
- **진행:** 한 번에 한 문제를 풀고, 답을 선택하면 **즉시 채점**된다. 정답이면 근거 구절이 함께 제시되고, 오답이면 정답과 해설이 제공된다. 사용자는 이어서 다음 문제로 계속 갈 수도, 언제든 세션을 끝낼 수도 있다.
- **성취 반영:** 정답에 대해 명예(포인트)가 쌓인다. 획득량은 난이도에 따라 다르다 `[튜닝]`.
- **재출제 처리(반복 채굴 방지):** 이미 맞힌 문제가 다시 나올 수 있으나, **재출제 문제의 성취 가치는 신규 문제보다 낮다** `[튜닝]`. 또한 최근에 푼 문제는 당분간 출제 우선순위가 낮아진다. → 쉬운 문제를 반복해 명예를 부풀리는 행위를 무력화한다.
- **콤보:** 정답이 연속되면 보너스가 누적된다 `[튜닝: 임계·배율]`. 오답이 나오면 콤보는 초기화된다.
- **오답 처리:** 오답인 문제는 성취를 주지 않고, 해설과 함께 **오답노트에 자동 저장**된다. 오답노트의 보관 범위·복습 기능의 깊이는 구독과 연계될 수 있다(I).
- **비정상 입력 방어:** 사람이 문제를 읽고 답하기에 지나치게 빠른 반복 입력이 감지되면 해당 세션의 성취를 무효화한다 `[튜닝: 임계]`. 이 방어는 정상 사용자에게는 보이지 않게 동작한다.
- **격리된 문제:** 오류로 격리된 문제(J)는 출제되지 않는다. 사용자가 풀던 중 어떤 문제가 격리되면, 그 문제는 결과·성취에서 제외 처리한다.
- **카테고리·난이도:** 사용자는 원하는 카테고리를 고르거나 통합 랜덤으로 풀 수 있다. 난이도는 초기 진단(B) 이후 실력 추이에 따라 자동 재보정된다.

**C.3 상태 (문제·세션)**
- 세션: `시작` → `진행(문제별 채점 누적)` → `종료(요약)`. 종료는 사용자가 언제든 트리거할 수 있다.
- 개별 문제(사용자 관점): `미출제` → `출제됨` → `정답/오답 처리` → (재출제 대상은) `쿨다운` → `재출제 가능`.

**C.4 사용자 시나리오**
- `정상` 사용자가 통합 랜덤으로 계속 풀며 콤보를 쌓다가 원하는 때 종료한다.
- `정상` 오답을 만나 해설을 읽고, 그 문제가 오답노트에 담긴 것을 나중에 복습한다.
- `정상` 특정 카테고리(예: 인물)만 골라 집중적으로 푼다.
- `경계` 아주 오래 연속으로 풀어 대부분의 신규 문제를 소진 → 재출제가 늘어나고, 재출제 성취가 낮아 명예 상승이 완만해진다(콘텐츠 소진 완충).
- `경계` 세션 도중 앱이 백그라운드로 가거나 종료됨 → 재실행 시 직전까지의 처리 결과는 보존되고, 중단된 문제는 미완료로 처리.
- `경계` 난이도가 실력과 크게 어긋남 → 연속 정답/오답 추이에 따라 자동으로 난이도가 재보정된다.
- `오류` 문제 로딩 실패(네트워크) → 재시도를 안내하고, 채점되지 않은 문제는 성취에 반영하지 않는다.
- `오류` 채점 요청이 중복 전송됨(연결 불안정) → 동일 문제는 한 번만 반영(멱등 처리).
- `악용` 매크로로 초고속 반복 입력 → 비정상 속도 감지로 해당 세션 성취 무효(C.2).
- `악용` 같은 쉬운 문제만 반복해 명예 채굴 시도 → 재출제 성취 하향·출제 우선순위 하향으로 무력화.

### D. 포인트·명예·등급

**D.0 개요.** 실력과 꾸준함을 **눈에 보이는 명예**로 인정한다. 명예는 현금·재화로 바뀌지 않으며, 한번 오른 등급은 내려가지 않는다.

**D.1 기능**
- 성취(포인트) 누적
- 등급 승급(누적 성취 기반, 하락 없음)
- 승급 축하 및 공유
- 등급·성취 배지(프로필·기여자 목록 등에서 사용)

**D.2 상세 동작**
- 퀴즈 정답, 출석 등으로 성취가 쌓이고, 누적 성취가 일정 수준에 이르면 **다음 등급으로 승급**한다 `[튜닝: 등급 체계·임계]`.
- 등급은 **하락하지 않는다.** 활동이 줄어도 이미 얻은 등급은 유지된다(중장년 사용자의 상실감 방지).
- **명예 전용 원칙:** 성취·등급은 환전·소비가 불가능하다. 구독 등 유료 요소가 명예·등급에 영향을 주지 않는다(경쟁 공정성).
- 승급 순간 **축하가 연출**되고, 사용자는 이를 **공동체와 공유**할 수 있다(공유는 자연스러운 유입 계기가 된다 → G/H와 연동).
- 등급/성취는 배지 형태로 사용자의 정체성 표식이 되며, 리더보드의 기여자 표기 등에서 함께 노출된다(E).

**D.3 상태**
`시작 등급` → (누적 성취 도달) → `상위 등급` → … (단조 증가, 하락 없음)

**D.4 사용자 시나리오**
- `정상` 꾸준히 풀어 다음 등급으로 승급 → 축하를 받고 공동체에 자랑을 공유.
- `정상` 한동안 쉬었다가 복귀 → 등급은 그대로 유지되어 상실감 없이 재개.
- `경계` 한 세션에서 큰 성취로 두 등급을 한 번에 통과 → 각 승급이 순서대로 인정되고 최종 등급이 반영.
- `경계` 부정 방어로 세션 성취가 무효화됨(C) → 해당 성취는 누적에 반영되지 않아 승급도 취소/미발생.
- `악용` 명예를 현금화·거래하려는 시도 → 구조적으로 불가(명예 전용).

### E. 리더보드 (개인 · 교회 대항)

**E.0 개요.** 나의 위치를 확인하고, 무엇보다 **"우리 교회"의 순위를 함께 지켜본다.** 교회 대항이 이 앱의 결정적 차별화다.

**E.1 기능**
- 개인 리더보드: 전국 / 시도(지역) / 우리 교회 내부
- 교회 대항 리더보드
- 규모 리그(교회 규모에 따른 리그 분리)
- 주간 랭킹(정기 리셋) + 누적 랭킹
- 내 순위·백분위 확인
- 교회 상세(순위 추이, 기여자, 참여 인원, 응원 공유)

**E.2 상세 동작**
- **개인 순위:** 전국·지역·우리 교회 내부에서 각각 나의 순위를 확인할 수 있다. 나의 순위와 백분위는 항상 확인 가능하다.
- **주간 리셋:** 랭킹은 주기적으로 리셋되어 후발 주자에게도 매주 기회를 준다. 누적 랭킹은 보조로 병행한다. `[튜닝: 리셋 주기·시점]`
- **교회 점수:** 개인의 성취가 우리 교회의 점수로 합산되어 교회 대항 순위를 만든다. 합산 방식은 **대형 교회의 인원 우위를 제한**하도록 설계한다(모든 인원 단순 합산이 아니라 대표 기여자 중심). `[튜닝: 합산 산식]`
- **규모 리그:** 교회를 활동 규모에 따라 리그로 나눠, 작은 교회도 자기 리그에서 겨룰 수 있게 한다. 전체 통합 순위는 참고로 병행한다. `[튜닝: 리그 경계]`
- **기여 감각:** 사용자는 자신이 우리 교회 순위에 얼마나 기여했는지 확인할 수 있고, 상위 기여자는 별도로 인정된다.
- **교회 상세:** 우리 교회(및 임의 교회)의 순위 추이, 기여자, 참여 인원을 확인하고, "우리 교회 응원"을 공동체에 공유할 수 있다.
- **부정 반영 차단:** C/G의 부정 방어로 무효화된 성취는 교회 점수에도 반영되지 않는다. 이상 패턴 교회는 운영 검토 대상이 된다(J/운영).

**E.3 상태**
- 랭킹 주기: `집계중(진행 주)` → `마감/리셋` → `새 주 시작`.
- 사용자-교회 관계에 따라 교회 대항 관련 항목의 노출/참여가 달라진다(교회 미등록 시 개인 리더보드만).

**E.4 사용자 시나리오**
- `정상` 사용자가 우리 교회 순위가 오른 것을 확인하고 공동체에 공유한다.
- `정상` 주간 리셋 후 새롭게 상위권에 도전한다.
- `정상` 자신이 우리 교회의 상위 기여자에 든 것을 확인하고 뿌듯함을 느낀다.
- `경계` 교회 미등록 사용자 → 개인 리더보드는 참여하되 교회 대항에는 참여할 수 없고, 교회 등록을 권유받는다.
- `경계` 우리 교회의 참여 인원이 적음 → 규모 리그에서 비슷한 규모의 교회와 겨루므로 참여 동기가 유지된다.
- `경계` 리셋 순간에 순위를 조회 → 마감/집계 상태가 일관되게 반영되어 값이 튀지 않는다.
- `악용` 특정 교회에서 조직적 부정으로 점수를 끌어올림 → 부정 성취 배제 + 이상 패턴 검토로 대응.

### F. 교회 (검색 · 등록 · 소속)

**F.0 개요.** 사용자가 자신의 교회를 앱 안에서 만나 **팀이 되는** 관문. 교회 대항의 선행 조건.

**F.1 기능**
- 교회 검색(이름·지역 기반)
- 소속 등록(내 교회로 지정)
- 검색에 없는 교회 직접 등록(운영 검수)
- 소속 변경(빈도 제한)
- 사전 등록(주요 교회 verified 시딩)
- 사회적 증거("N명의 성도가 함께")

**F.2 상세 동작**
- 교회명을 입력하면 지역·주소가 함께 표시된 후보들 중에서 선택한다. **동명 교회**는 지역 표기로 구분한다.
- 이미 등록된 교회에는 함께하는 성도 수가 표시되어(사회적 증거) 등록 전환을 돕는다.
- **검색에 없는 개척 교회**는 직접 등록할 수 있고, 이 경우 운영 검수 대기 상태로 접수된다.
- **소속 변경은 빈도가 제한**된다(대항전 시즌 중 팀을 갈아타는 행위 방지). `[튜닝: 변경 주기]`
- 신뢰 확보를 위해 주요 대형 교회는 **사전에 검증(verified) 등록**되어 있다.
- 소속이 확정되면 사용자는 그 교회의 성도로서 교회 대항·교회 내부 리더보드·기여에 참여한다.

**F.3 상태 (교회 / 소속)**
- 교회: `verified(사전 검증)` / `사용자 등록·검수중` / `검수 완료` / `반려·병합`(중복·허위 처리).
- 소속: `미소속` → (등록) → `소속(우리 교회)` → (변경 제한 내 변경) → `다른 교회 소속`.

**F.4 사용자 시나리오**
- `정상` 교회명을 검색해 지역으로 우리 교회를 특정하고 소속으로 등록.
- `정상` 우리 교회가 아직 없어서 직접 등록 → 검수 후 정식 반영, 그동안 임시로 참여 가능 여부는 [상세 설계].
- `경계` 동명 교회가 여럿 → 지역 표기로 구분해 정확히 선택.
- `경계` 최근에 소속을 바꿔 변경 제한에 걸림 → 다음 변경 가능 시점을 안내.
- `경계` 이사·교회 이동으로 실제 소속이 바뀜 → 변경 제한 내에서 이전.
- `오류` 검색 결과가 없음 → 직접 등록 경로로 자연스럽게 유도.
- `악용` 허위 교회를 만들어 점수를 몰아주려는 시도 → 검수·중복 병합·이상 패턴 검토로 차단.

### G. 초대 · 성장

**G.0 개요.** "한 명이라도 더 데려오면 우리 교회가 이긴다"는 구조를 개인의 명예로 증폭한다. 별도 채널이 아니라 **교회 대항의 연장**이다.

**G.1 기능**
- 초대 링크(공유로 설치·가입 시 자동 귀속)
- 초대 코드(링크 유실·수동 전달 대응)
- 유효 초대 판정(어뷰징 방어)
- 초대 현황(누적 초대, 진행 상태 구분)
- 초대왕(정기 인정, 명예 전용)
- 맥락 기반 초대 독려

**G.2 상세 동작**
- 사용자는 초대 링크를 공동체에 공유할 수 있고, 그 링크로 설치·가입한 사람은 **자동으로 초대자에게 귀속**된다(코드 입력 불필요). 링크가 유실된 경우를 위해 **초대 코드** 수동 입력도 제공한다.
- **유효 초대 판정:** 단순 가입만으로는 실적으로 인정되지 않는다. 피초대자가 **일정 조건(가입 + 교회 등록 + 일정량의 퀴즈 완료)** 을 모두 충족해야 "유효 초대"로 인정된다. 그 전까지는 "대기 중"으로만 표시한다. `[튜닝: 완료 기준]`
- **어뷰징 방어:** 동일 기기 반복 가입 차단, 1인당 기간 내 인정 상한, 이상 패턴(단기 대량 초대)의 운영 검토가 함께 작동한다. `[튜닝: 상한]`
- **초대 현황:** 사용자는 자신의 누적 초대와, "가입만 한 사람 / 활동을 시작한 사람"을 구분해 진행 상태를 확인한다.
- **초대왕:** 일정 기간 단위로 초대 실적을 인정한다. 보상은 **명예 전용**(배지·마일스톤)이며 성취(포인트)는 지급하지 않는다 → 실력 랭킹과 초대 실적을 분리해 각 순위의 순수성을 지킨다.
- **맥락 기반 독려:** 사용자가 이미 공유 동기를 가진 순간(예: 승급 직후, 우리 교회 순위 상승·근접, 주간 결산)에만 초대를 권유한다. 트리거 없는 반복 권유는 최소화하고, "다시 보지 않기"를 항상 제공하며, **퀴즈 진행 중에는 권유하지 않는다.** `[튜닝: 빈도 상한]`

**G.3 상태 (초대)**
`발송/공유` → 피초대자 `가입(대기 중)` → (조건 충족) → `유효 초대 인정` / (기기 중복·상한·이상) → `무효/보류`

**G.4 사용자 시나리오**
- `정상` 사용자가 승급 직후 초대를 공동체에 공유 → 지인이 링크로 설치·가입·교회 등록·퀴즈 시작 → 유효 초대로 인정.
- `정상` 링크가 유실된 지인에게 코드로 안내 → 코드 입력으로 귀속.
- `경계` 지인이 가입만 하고 조건 미충족 → "대기 중"으로 표시되고 유효 초대에는 아직 미반영.
- `경계` 초대받은 사람이 이미 다른 초대자에게 귀속됨 → 중복 귀속 없이 최초 귀속만 유지.
- `악용` 같은 기기로 여러 계정을 만들어 자기 초대 실적을 부풀림 → 동일 기기 차단으로 무효.
- `악용` 단기간 대량 초대로 순위 조작 → 인정 상한 + 이상 패턴 검토로 방어.
- `경계` 초대 권유가 반복돼 피로 → 맥락 한정·빈도 상한·다시 보지 않기로 완화.

### H. 리텐션 (출석 · 오늘의 말씀 · 알림 · 주간 결산)

**H.0 개요.** 매일의 신앙 습관에 자연스럽게 얹혀, 다시 돌아올 이유를 만든다.

**H.1 기능**
- 출석 체크(연속 출석 인정 + 소량 성취)
- 오늘의 말씀(매일 한 구절)
- 알림(푸시): 교회 순위 변동, 연속 출석 리마인드, 주간 마감 임박
- 주간 결산(지난주 우리 교회 성적)

**H.2 상세 동작**
- **출석:** 매일 방문/활동으로 출석이 인정되고, 연속 출석에 대해 마일스톤이 인정된다(+소량 성취). 연속이 끊기는 기준은 [상세 설계].
- **오늘의 말씀:** 매일 한 구절이 제공되어 QT 습관과 연결되는 정서적 앵커가 된다.
- **알림:** 사용자가 돌아올 만한 사건(우리 교회 순위 변동, 연속 출석 유지 리마인드, 주간 마감 임박)에 한해 알림을 보낸다. **알림 빈도에는 상한이 있다** `[튜닝: 일 상한]`. 사용자는 알림 수신을 설정에서 제어할 수 있다(K).
- **주간 결산:** 한 주가 마감되면 "지난주 우리 교회 성적"이 정리되어, 공동체 공유를 유도하는 정기 트리거가 된다(G와 연동).

**H.3 상태**
- 출석: `오늘 미출석` → (방문/활동) → `오늘 출석` ; 연속 카운트는 매일의 연속성에 따라 증가/초기화.
- 알림: 사용자 설정(허용/차단) × 사건 발생 × 빈도 상한의 조합으로 발송 여부 결정.

**H.4 사용자 시나리오**
- `정상` 매일 접속해 출석을 이어가며 연속 출석 마일스톤을 달성.
- `정상` "우리 교회가 순위 올랐다"는 알림을 받고 재진입 → 확인 후 공유.
- `정상` 월요일 아침 주간 결산을 받아 구역방에 공유.
- `경계` 하루 접속을 놓쳐 연속 출석이 끊김 → 다음 방문부터 다시 시작.
- `경계` 여러 사건이 동시에 발생 → 빈도 상한 내에서 중요도에 따라 선별 발송(과도한 알림 방지).
- `오류` 알림 권한이 없거나 꺼져 있음 → 인앱에서 동일 정보를 확인할 수 있게 보완, 권한 안내는 강요하지 않음.

### I. 수익화 경험 (광고 · 구독)

**I.0 개요.** 광고가 대중을, 구독이 몰입층을 지탱한다. 단, **명예·경쟁의 공정성에 영향을 주는 혜택은 없다.** 이 절은 수익화의 *사용자 경험*만 다룬다(정확한 노출 규칙·가격은 `[튜닝]`).

**I.1 기능**
- 전면 광고(풀이 흐름의 자연스러운 구획 지점에서 노출)
- 보상형 광고(선택적으로 시청하고 이득을 얻음)
- 배너 광고(집중을 해치지 않는 맥락에 한정)
- 구독(가입 · 혜택 · 해지 · 복원 · 상태 관리)

**I.2 상세 동작**
- **전면 광고:** 문제 풀이 *도중이 아니라* 일정 분량을 마친 **구획 지점**에서 노출된다 `[튜닝: 주기]`. 몰입을 끊지 않도록 흐름의 마디에 배치한다.
- **보상형 광고:** **강제가 아니라 선택**이다. 사용자가 원할 때 시청해 이득(예: 일정 구간 성취 가중)을 얻는다. 명예 전용 구조이므로 현금성 pay-to-win 논란이 없다. 단, 보상형으로 얻은 이득이 **교회 대항 등 공정성 민감 영역**에 미치는 범위는 제한한다 `[상세 설계]`.
- **배너:** 집중을 요하는 퀴즈 흐름에는 노출하지 않고, 정보성 맥락(리더보드·통계 등)에 한정한다.
- **구독:** 월/연 단위로 가입한다 `[튜닝: 가격]`. 혜택은 **"공부 도구 + 후원"** 성격으로 한정된다 — 광고 제거, 오답노트·통계 심화, 후원자 표식 등. **성취·등급·순위에 영향을 주는 혜택은 절대 포함하지 않는다.**
- **구독 상태:** 가입/갱신/해지 예약/만료/복원(기기 변경·재설치 시 이전 구매 복원)을 지원한다. 결제·영수증의 유효성은 서버에서 검증한다.

**I.3 상태 (구독)**
`무료` → (가입) → `구독 중` → (해지 예약) → `해지 예약(만료일까지 혜택 유지)` → (만료) → `무료` ; (복원) → `구독 중`

**I.4 사용자 시나리오**
- `정상` 헤비 사용자가 광고가 흐름을 끊는다고 느껴 구독으로 광고를 제거.
- `정상` 사용자가 보상형 광고를 선택 시청해 이득을 얻음(원치 않으면 무시).
- `정상` 구독자가 오답노트·통계 심화를 활용해 학습.
- `경계` 구독 해지 → 남은 기간까지 혜택 유지 후 무료로 전환.
- `경계` 기기 변경·재설치 → 이전 구독을 복원.
- `오류` 광고 로딩 실패 → 광고 없이 흐름을 계속 진행(사용자 경험을 막지 않음).
- `오류` 결제 실패·중단 → 혜택 미부여, 명확한 실패 안내와 재시도.
- `악용` 위조 영수증으로 혜택 탈취 시도 → 서버 검증으로 차단.
- `공정성` 구독자가 순위에서 유리해지길 기대 → 구조적으로 불가(순위 영향 혜택 없음).

### J. 오류 신고 · 신뢰

**J.0 개요.** 사용자를 **품질 관리의 동역자**로 만든다. 성경 오류 하나가 앱 전체 신뢰를 무너뜨리는 사용자층이므로, 신고는 단순 CS가 아니라 신뢰 인프라다.

**J.1 기능**
- 오류 신고(원탭 사유 선택 + 자유 입력)
- 접수 즉시 피드백
- 자동 격리(신고·정답률 이상 등으로 출제 풀에서 임시 제외)
- 신고 채택 시 알림 + 소량 성취
- 신고자 마일스톤 인정(누적 채택)

**J.2 상세 동작**
- 문제 해설 맥락에서 **오류 신고를 실행**할 수 있다. 사유는 **원탭 선택**(정답이 틀림 / 근거 구절이 다름 / 오타·표기 / 문제가 모호함 / 기타)으로, 긴 글을 쓰지 않아도 신고할 수 있다.
- 신고 접수 즉시 **"확인 후 알려드리겠다"** 는 피드백을 준다.
- **자동 격리:** 특정 문제에 신고가 누적되거나, 정답률 등 지표가 이상치를 보이면(문제 자체 오류 신호) 그 문제를 **출제 풀에서 자동 임시 제외**한다 `[튜닝: 임계]`. 신고가 없어도 지표만으로 격리가 발동해 이중 감시망이 된다.
- **처리 결과 반영:** 검증 결과 문제가 수정되면, **신고자에게 알림과 소량 성취**를 준다("회원님의 제보로 문제가 바로잡혔어요"). 신고가 채택되며 누적되면 마일스톤으로 인정한다(명예). 신고가 기각되면 문제는 다시 출제 풀로 복귀한다.
- (자동 검증·수리 파이프라인의 내부 처리 규칙과 SLA는 운영/콘텐츠 상세 설계에서 정의. 이 문서는 사용자 관점만 다룬다.)

**J.3 상태 (문제 신뢰)**
`정상 출제` → (신고 누적/지표 이상) → `격리(비출제)` → (검증) → `수정 후 복귀` / `기각 후 원복` / `폐기`

**J.4 사용자 시나리오**
- `정상` 사용자가 정답이 틀렸다고 판단해 원탭으로 신고 → 접수 피드백 → 이후 채택되어 알림 + 소량 성취.
- `정상` 신고가 누적 채택되어 신고자 마일스톤 인정.
- `경계` 여러 사용자가 같은 문제를 신고 → 누적으로 자동 격리 발동, 격리 후에는 해당 문제가 더 이상 출제되지 않음.
- `경계` 신고가 사실은 오해였음(문제 정상) → 검증 후 기각, 문제는 복귀하고 사용자에게 과한 불이익은 없음.
- `경계` 내가 방금 푼 문제가 직후 격리됨 → 그 문제의 결과·성취는 제외 처리.
- `오류` 신고 전송 실패 → 재시도 안내, 중복 신고는 한 건으로 정리.
- `악용` 특정 문제를 떨어뜨리려 조직적 허위 신고 → 지표(정답률 등) 교차 검증과 검수로 무분별한 격리·수정 방지.

### K. 설정 · 접근성 · 계정 관리

**K.0 개요.** 중장년 사용자가 스스로 통제감을 갖도록, 필요한 최소한의 설정을 단순하게 제공한다.

**K.1 기능**
- 글씨 크기(전역 큰 글씨)
- 알림 수신 설정
- 표기 기준 고지(용어·번역 표기 원칙)
- 계정 관리(로그아웃, 탈퇴, 구독 관리 진입)
- 데이터·개인정보 관련 항목(정책 열람 등) `[상세 설계: 법무 연계]`

**K.2 상세 동작**
- **글씨 크기:** 전역적으로 키울 수 있으며, 선택은 즉시 전 기능에 반영된다(B에서 최초 선택, 이후 언제든 변경).
- **알림:** 사용자는 알림 수신을 켜고 끌 수 있다(H와 연동). 세부 종류별 제어의 깊이는 [상세 설계].
- **표기 기준 고지:** 인명·지명·용어의 표기 표준을 안내해, 표기 혼선으로 인한 오해를 줄인다.
- **계정 관리:** 로그아웃, 탈퇴(A와 연동), 구독 관리로의 진입을 제공한다.

**K.4 사용자 시나리오**
- `정상` 글씨가 작다고 느낀 사용자가 크기를 키움 → 즉시 전체가 커짐.
- `정상` 알림이 많다고 느껴 특정 알림을 끔.
- `경계` 탈퇴를 선택 → 되돌릴 수 없음을 고지받고 확인 후 진행(A.2).

## 3. 교차 사용자 시나리오 (End-to-End)

여러 기능을 가로지르는 대표 여정. 각 여정은 위 기능들이 어떻게 연결되는지를 보여준다.

### S1. 신규 사용자 온보딩 완주 (P1형)
로그인(A) → 큰 글씨 선택(B/K) → 난이도 진단(B, 광고 없음) → 첫 성취 부여(B/D) → 교회 검색·등록(F) → 통합 랜덤으로 퀴즈 시작(C) → 첫 명예 획득(D) → 개인·교회 리더보드에서 내 위치 확인(E) → (맥락 트리거로) 초대 권유 받음(G).

### S2. 교회 없이 시작 → 나중에 합류
교회 등록을 건너뜀(B) → 퀴즈·명예·개인 리더보드는 정상 사용(C/D/E) → 교회 대항 항목에서 "교회를 등록하면 함께 겨룰 수 있다"는 유도를 반복적으로 받음 → 이후 교회 등록(F) → 그 시점부터 교회 점수에 기여 시작(E).

### S3. 헤비 사용자의 하루 (P2형)
출퇴근길에 장시간 풀이(C) → 콤보 누적 → 신규 문제 소진으로 재출제 비중 증가·명예 상승 완만(C) → 승급 달성(D) → 승급 축하를 공유(D/G) → 광고가 흐름을 끊는다고 느껴 구독으로 광고 제거(I) → 우리 교회 상위 기여자에 진입(E).

### S4. 전파자의 캠페인 (P3형)
우리 교회가 아직 순위에 없음을 발견(E/F) → 교회 직접 등록 또는 확인(F) → 초대 링크를 공동체 단체방에 공유(G) → 여러 지인이 설치·가입·교회 등록·퀴즈 시작 → 유효 초대로 인정되며 교회 참여 인원·점수 상승(G/E) → 주간 결산으로 성과 확인·재공유(H).

### S5. 네트워크 저하·오프라인
풀이 중 연결 불안정(C) → 채점 실패 문제는 성취 미반영, 재시도 안내 → 중복 전송은 멱등 처리 → 연결 복구 후 이어서 진행 → 광고 로딩 실패 시 광고 없이 계속(I) → 알림은 연결 복구 후 지연 도달 가능(H).

### S6. 주간 리셋 전후
마감 임박 알림 수신(H) → 막판 풀이로 순위 도전(C/E) → 리셋 순간 조회 시 집계/마감 상태 일관 반영(E) → 새 주 시작 → 누적 랭킹은 유지, 주간 랭킹은 초기화 → 주간 결산 수신·공유(H/G).

### S7. 구독 생애주기
무료로 사용(I) → 가입 → 광고 제거·학습 심화 활용 → 해지 예약 → 만료일까지 혜택 유지 → 무료 전환 → 이후 기기 변경 시 이전 구매 복원(I). 이 전 과정에서 명예·순위에는 아무 변화 없음(공정성).

### S8. 오류 발견 → 채택
풀이 중 정답 오류 의심(C) → 원탭 신고(J) → 접수 피드백 → (신고 누적/지표 이상으로) 자동 격리 → 검증 후 수정·복귀 → 신고자에게 알림 + 소량 성취 + 누적 시 마일스톤(J/D).

### S9. 어뷰징 시도 → 방어 (통합)
매크로 초고속 입력(C) → 세션 성취 무효 · 다계정·동일 기기 초대(G) → 유효 초대 무효 · 쉬운 문제 반복 채굴(C) → 재출제 성취 하향 · 조직적 교회 점수 조작(E) → 부정 성취 배제 + 이상 패턴 검토 · 허위 신고(J) → 지표 교차 검증. → 어떤 경로로도 명예·순위·성장 지표가 오염되지 않는다.

### S10. 계정 탈퇴
설정에서 탈퇴 선택(K) → 되돌릴 수 없음 고지 → 확인 → 개인 식별·활동 이력 파기, 누적 명예·교회 기여·초대 귀속의 처리 규칙 적용(A.2, `[상세 설계]`).

## 5. 이 문서에서 의도적으로 유보한 것 (→ 상세 설계)

기능의 **동작 방식·규칙·시나리오**는 위에서 정의했으나, 아래의 **구체 수치·산식·내부 처리 규칙**은 밸런싱/상세 설계 문서에서 확정한다. (본문 `[튜닝]`·`[상세 설계]` 표시 지점)

- 포인트 획득량, 재출제 감소율, 콤보 임계·배율
- 등급 체계와 승급 임계값
- 광고 노출 주기·형식, 보상형 이득의 크기와 공정성 경계
